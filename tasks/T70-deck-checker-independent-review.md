## 背景：为什么要有这张卡

T65 交付了 6 条可执行的判据（4 强 + 2 弱 warning），22/22 全绿，每条都有正控 + 负控。**但它验的是「该报的报了、不该报的没报」——用的是作者自己造的夹具。**

作者造夹具时脑子里已经知道判据长什么样，于是很容易造出「正好卡在判据边界外」的合规页。**这在测试里看不见，在真实模型写 spec 时会立刻暴露。**

而这次失败模式的代价不对称：

- **漏报**：模型写了个空的页面，没被抓住 —— 退化成今天的样子，不更糟；
- **误报**：模型写了合规的页面，被判成缺陷，于是去改 —— **它会把对的东西改坏**。

所以本卡的重点是**误报**。

## 任务

### 一、读代码，逐条判断强度（不需要跑套件）

读 `apps/desktop/src/main/document/deckPatternCheck.ts`，对每条判据回答：

| 问题 | 为什么要问 |
|---|---|
| 阈值是**拍的**还是**从数据推的**？ | 拍的阈值在样本外一定出问题 |
| 误报的**边界情形**是什么？ | 找出来去测 |
| 判据报的是**确定缺陷**还是**疑似**？ | T65 卡要求「弱版本要如实标注，不要当确定缺陷报」 |

重点看：

- `NOT_IMPLEMENTED` 里的三条（装饰角落 / 两行同义 / 混用量纲）：**理由站得住吗？** 有没有其实能用保守判据做的？（作者说不做，不代表真做不到）
- 两条「弱（warning）」（构图雷同、页眉条）：**弱在哪？** 会不会大量误报？

### 二、误报测试（本卡的核心）

**构造 5 个「合规但非典型」的页面**，喂给 `checkDeckPatterns()`，看会不会被报。

必须覆盖这几种（可以合并）：

| # | 页面形态 | 为什么它合规 |
|---|---|---|
| 1 | **极简封面**：少量文字 + 大面积留白 | 留白是设计手段，不是缺陷 |
| 2 | **满版大图页**：几乎没有文字，全是图 | 视觉页本来就不该塞文字 |
| 3 | **4 张卡片**的页 | 判据若按「3 张」写死会误报 |
| 4 | **纵向列表**页（不是卡片阵列） | 版式合法 |
| 5 | **closing 页只放一行大字** | 收尾页本来就该空 |

对每个：输入摘要 + 实际输出 + **你认为该不该报** + **如果不该报而报了，是判据的哪一行导致的**。

### 三、漏报测试

1. 用 T62 三根空柱子的形态（内容只铺到约 0.667）造一页 → **必须被报**；
2. 造 0.79 / 0.85 两页 → 看阈值边缘的行为是否可解释。

### 四、结论

明确回答：**这套检查器现在能不能给模型用？**

- **能用** → 附带条件（哪些 warning 应该降级成提示、哪些不能当确定缺陷）；
- **不能用** → 缺什么、最危险的误报是哪条。

## 验收判据

1. 逐条判据强度判断表（阈值来源 / 误报边界 / 确定 vs 疑似）。
2. **5 个误报夹具的实际运行结果**（不能只写「我觉得不会误报」，要跑）。
3. 漏报测试的实测结果。
4. 明确结论 + 附带条件。
5. **不改产品代码**。
