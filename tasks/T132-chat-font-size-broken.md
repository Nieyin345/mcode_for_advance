# T132｜728 处硬抄的字号系数让「对话字号」设置基本失效

## 零、缺陷（我数过）

```
用 var(--chat-fs-*) 变量        55 处
硬抄系数 text-[0.7857em] 等     728 处
```

而这些系数**就是变量本身的值**（`styles.css:618-620`）：

```css
--chat-fs-sm:  calc(var(--chat-font-size) * 0.9286);
--chat-fs-xs:  calc(var(--chat-font-size) * 0.8571);
--chat-fs-xxs: calc(var(--chat-font-size) * 0.7857);
```

**`text-[0.8571em]` 的视觉效果 = `var(--chat-fs-xs)`，但它不跟 `--chat-font-size` 变。**

### 后果

用户在设置里调「对话字号」（`--chat-font-size`），**只有那 55 处跟着变，728 处纹丝不动。**

**这是「设置点了没反应」的一个具体来源。** 而且它比「字号不统一」严重 —— 前者是**功能失效**，后者是**观感问题**。

## 一、先验证这个判断（不要直接改）

**在动手之前，先跑一个最小实验**：

1. 把 `--chat-font-size` 从 14px 改成 20px；
2. **看界面上哪些字变大了**；
3. 如果只有少数变大，而大部分不变 —— **确认缺陷**。

**⚠️ 这个实验必须在真机或 preview 里做**，因为在 CSS 里改一个变量，headless 量不出视觉结果。

**如果做不了视觉验证**，改用静态判断：

```bash
# 找出所有硬抄系数的位置
grep -rn "text-\[0\.7857em\]\|text-\[0\.8571em\]\|text-\[0\.9286em\]\|text-\[0\.7143em\]" \
  apps/desktop/src/renderer/ --include=*.tsx
```

**把每一处的值换算成「它相当于哪一档」**：

| 硬抄值 | 对应变量 | 尺寸（14px 基准） |
|---|---|---|
| `0.6428em` | ？ | 9px |
| `0.7143em` | ？ | 10px |
| `0.7857em` | `--chat-fs-xxs` | 11px |
| `0.8571em` | `--chat-fs-xs` | 12px |
| `0.9286em` | `--chat-fs-sm` | 13px |
| `0.9em` / `0.85em` / `0.92em` | **没有对应变量** | 零碎值 |

**前两行（`0.6428` / `0.7143`）在 `--chat-fs-*` 里没有对应项** —— 它们是「比 xxs 还小」的字。**这 239 + 15 处需要单独判断。**

## 二、修法

### 第一批：有直接对应变量的

```diff
- className="text-[0.7857em]"
+ className="[font-size:var(--chat-fs-xxs)]"
```

```diff
- className="text-[0.8571em]"
+ className="[font-size:var(--chat-fs-xs)]"
```

```diff
- className="text-[0.9286em]"
+ className="[font-size:var(--chat-fs-sm)]"
```

**⚠️ 用 `[font-size:var(--...)]` 而不是 `text-[var(--...)]`。** 后者在 Tailwind 里也能用，但 `text-` 前缀同时管颜色和字号，容易混淆。**先确认项目里现有 55 处用的是什么写法，保持一致。**

```bash
grep -rn "var(--chat-fs" apps/desktop/src/renderer/ --include=*.tsx | head -5
```

### 第二批：没有对应变量的（`0.6428` / `0.7143` / 零碎值）

**239 处 `0.7143em`（=10px）** 和 **15 处 `0.6428em`（=9px）**。

**这两个值在规范七档里没有对应。** 判断和 T130 一样：**先看它们是什么场景，再决定「新增档位」还是「归并」**。

## 结果回写（2026-10-24，K）

### 零、★ 结论先行：**393 处里只有 7 处是真缺陷**

**卡上把「728 处 em」当成一个整体缺陷，实测不是。**

| 位置 | 处数 | `em` 有效吗 | 为什么 |
|---|---|---|---|
| `components/settings/` | **301** | ✅ **有效** | `SettingsPage.tsx:345/420` 显式设了 `style={{ fontSize: "var(--right-panel-font-size)" }}` |
| `components/library/` 等 | 85 | ✅ 多数有效 | 同上（`TurnFlowPanel.tsx:234/306` 同一模式） |
| **`components/chat/`** | **7** | ❌ **失效** | 聊天根 `[data-chat-root]` **不设字号**，只有气泡内部用 `[font-size:var(--chat-font-size)]` |

**所以只改了 7 处。** 把 301 处 settings 的 `em` 改成 `var(--chat-fs-*)` 会是**新的缺陷** —— 那会让面板文字跟着「对话字号」变，而不是跟着「面板字号」变。

### 一、实验做了（浏览器实测，不是推的）

用 Chromium 跑 `.tmp/t132/probe.html`，body 取浏览器默认 16px（模拟真实应用：`--chat-font-size` 只写在 `<html>`，**不写进任何元素的 font-size**）：

```
--chat-font-size: 14px →  text-[0.8571em] = 13.71px    var(--chat-fs-xs) = 12.00px
--chat-font-size: 20px →  text-[0.8571em] = 13.71px    var(--chat-fs-xs) = 17.14px
                            ^^^^^^^^^^ 纹丝不动          ^^^^^^^^^^ 跟着变
```

**两个结论**：
1. 调「对话字号」时，em 写法**完全不动**；
2. **即便在默认 14px 下，两者也本来就不相等**（13.71 vs 12.00）。

**这个实验证明了缺陷存在，不只是数值上看起来一样。**

### 二、改了什么

7 处全部从 `text-[0.XXXXem]` 换成 `[font-size:var(--chat-fs-*)]`（与仓库里现有 55 处的写法一致）：

| 文件 | 处数 | 换成 |
|---|---|---|
| `ChunkedMarkdown.tsx` | 1 | `--chat-fs-xxs` |
| `EmptyThreadWelcome.tsx` | 2 | `--chat-fs-xxs` ×1、`--chat-fs-xs` ×1 |
| `SearchFilterBar.tsx` | 3 | `--chat-fs-xxs` |
| `WorkflowBoardPanel.tsx` | 1 | `--chat-fs-xxs` |

**聊天区 `text-[0.XXXXem]` 从 7 → 0。**

### 三、没动的 254 处（`0.7143em` / `0.6428em`）

**在 `--chat-fs-*` 里没有对应项**：
- `0.7143em` = 10px、`0.6428em` = 9px，都**小于** `--chat-fs-xxs`（11px）；
- 它们用在「比最小档还小」的场景。

**而且它们绝大多数在 settings 里，那里的 em 是有效的。** 所以本卡不动，记成「需要单独判断」。

### 四、套件与变异

`t132-chat-em-smoke`（新建，**14/14**）。四节：聊天区零 em / 变量真的被用起来 / 变量定义仍在 / **负控：面板的 em 不该被误伤**。

| 变异 | 正控（该红） | 实际 |
|---|---|---|
| 把一处改回 `text-[0.7857em]` | 1 | **1** ✓ |
| **删掉一处字号声明**（不是换写法） | 1 | **第一版全绿 → 加逐文件下限后 1 红** ✓ |
| `--chat-fs-xs` 改名 | 1 | **1** ✓ |

**第二行是本卡最重要的自我修正**：第一版只断言「总数 ≥ 7」，而实际有 53 处 —— 删一处还剩 52，**够不到下限**。改成**逐文件下限**（那 4 个文件各自的迁移数不许减少）之后才抓住。

**「总量守恒允许内部搬移」** —— 这是「按出口数守」和「按总量守」的区别。

### 五、觉得不对但没改的

- **85 处在 `library/` / `customUi/` / `ide/`** —— 我抽查了 `TurnFlowPanel` 有 `fontSize` 设置，但**没有逐个核实那 22 个文件**。它们可能有一半有效、一半失效。
- **`--rp-fs-*` 与 `--chat-fs-*` 的系数完全相同**（`0.7857` / `0.8571` / `0.9286`），意味着两个体系是同一套数字的两个基数。**这在结构上是隐患**：谁改了系数就得改两处。注释里没写这件事。
