## 为什么要单独一个目录

我在 `tasks/` 下连续两次撞编号：

- 第一次用 T126，撞了「`document_md_edit` 走 T125 的 `restorable` 路」；
- 改成 T129，又撞了另一个总控的终端卡（`aab0b70d`）。

**根因不是手滑，是我在别人的号段里抢号。** 两个总控并行时，主索引的号是共享资源，谁写卡前不自查就会撞。

**所以这条线的卡从 `F001` 独立编号，不占用 `T` 号段。** 主索引 `tasks/README.md` 里不再登记 F 卡。

## 编号规则

- `F001`、`F002`……**连续编号，不跳号、不复用**；
- 文件名 `F<NNN>-<slug>.md`；
- 已归档/作废的卡**保留在目录里，状态标记为 `wontfix` 或 `superseded`**，不删——删了下一个发卡的人又会撞号。

## 发卡前的自查（写在这里，免得又忘）

1. **`ls tasks/F/` 看最后一个编号**，下一个 +1；
2. **不要用 `T` 号段**——那是另一个总控的；
3. **不要改 `tasks/README.md`**——那是共享索引，归另一个总控维护；
4. 卡要改的文件如果落在 UI 线（`styles.css` / `tailwind.config.js` / `components/**`），**先跟另一个总控说一声**。

## 与主目录的关系

- F 卡的产出物（代码、文档、套件）**照常进仓库正常路径**，只有「卡本身」放这里；
- 套件目录名不带 `t` 号：`apps/desktop/scripts/<slug>-smoke/`；
- 如果一张 F 卡最终变成长期主线，由另一个总控决定要不要升格成 `T` 号写进主索引。
