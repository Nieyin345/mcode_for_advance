# O7｜让「覆盖范围」出现在每次运行的输出里，不只是卡上

- Status: **ready-for-agent**
- Category: **Office / 取证纪律**
- Priority: **P1 —— 它不是 bug，但它决定下一个读日志的人会不会误判**
- Depends on: O0（`0591acbc`）、O3（`f383922b`）

## 一、这条从哪来

UI 线在修 `run.sh` 守卫时写了一句话，我认为它是今天最值得抄的做法：

> **静态检查：抓 4 种已知拼写（`$0` / `SELF` 中转 / `BASH_SOURCE` / `${0%/*}`），不是穷举。
> 穷举请跑 `--deep`。**
>
> **这一行必须打出来。** 理由：有人加了一种新拼写而没加进模拟器，
> 至少读者知道「这里只覆盖 4 种」。

**它是「没有假装守住」的具体形态** —— 不是注释里写一句免责，是让边界出现在**每次输出**里。

## 二、Office 这边的现状

**O0 的边界写在卡的 7.1 回写区**：

> 它证明的是**这六份样本 × 这六类编辑**；不是「任意文档任意编辑」。

**但跑一次 `o0-format-fidelity-smoke` 的输出里，没有这句话。** 输出是：

```
journey 3/6 ... PASS
U1 suite: 6 journeys — all-pass=6
```

**一个只看日志的人，会把「6 journeys all-pass」读成「六格式都验过了」。**

**这正是 O0 自己在回写里警告过的那个误读，只是它写在卡上，而读日志的人不看卡。**

## 三、判据

**每次运行结束时，输出里必须有一行明确的覆盖边界。**

### 3.1 具体要打什么

| 套件 | 必须打的一行 |
|---|---|
| `o0-format-fidelity-smoke` | `覆盖：6 份样本 × 49 项断言；**未覆盖**：任意文档的任意编辑、PDF 旋转的视觉呈现、PPTX 真实模板的占位符继承` |
| `o3-packaged-smoke` | `覆盖：解压态产物、Windows x64、仅打开与渲染；**未覆盖**：NSIS 安装器、其它 OS、编辑保存重开` |
| `o1-three-provider-ai-smoke` | `覆盖：三家协议形状 + 错误/取消/负控；**未覆盖**：真实 API 调用（本机无凭据）` |

### 3.2 格式要求（这条是重点）

**必须是机器可读的固定前缀**，不是自由文本，而且是**三行**：

```
TIER: smoke（局部，改动相关）| u1（真 Electron 全量）| deep（长期跑）
COVERAGE: <覆盖了什么>
NOT-COVERED: <没覆盖什么>
```

理由：将来可以 `grep '^NOT-COVERED:'` 汇总出「我们到底还差什么」。
**自由文本的边界声明，三个月后就没人能聚合了。**

**`TIER` 这一行是 UI 线补的，比我原来的两行更完整** —— 它回答了「我在哪一档」。
`pnpm test:smoke` 跑的是局部，`t7`/`o0` 那套真 Electron 是另一档，
**而这两档的差别现在也没出现在输出里**。

### 3.3 不许只写在注释或卡里

**判据**：跑一次套件，`stdout` 里能看到那两行。**看不到就是没做。**

## 四、变异

1. **把 `NOT-COVERED:` 那行删掉** → 判据必须红；
2. **把前缀改成自由文本**（比如 `注意：本套件没覆盖 X`）→ 判据必须红
   （证明它验的是**格式**，不只是「有这句话」）；
3. **把 `TIER` 那行删掉** → 判据必须红（证明「我在哪一档」也被守住了）。

## 五、不要做的事

- **不要为了「让边界看起来小」而少写未覆盖项。** 这一行的价值在于**诚实**，不在于好看。
- **不要把它写成动态生成的**（比如从断言反推）。**手写，因为「没覆盖什么」是判断，不是推导。**
- **不要改断言本身**。这是输出层的改动。
