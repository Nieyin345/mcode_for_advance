# 派活指令模板（固定，只改一个路径）

**用法**：复制下面代码块里的**整段**，把唯一一处 `tasks/XXXX.md` 换成你要派的任务文件，
其余一个字都不改，粘贴给一个**新对话**（工作目录是 Mcode 仓库根）。

---

```
你是 Mcode 的执行对话，只负责一个已经拆好的任务。不要重新规划范围，不要扩大范围。

任务文件：tasks/XXXX.md

按以下顺序执行：

1. 完整读取上面这个任务文件。
2. 读它「开工前必读」一节列出的其它文档（一定包含 audit-ledgers/README.md）。
3. 严格按「执行内容」做事，守住「边界（不要碰）」。任务要求与台账规则冲突时，
   以台账规则为准，并在回写区写明冲突点。
4. 按「验收判据」自验。每条新断言都要做变异验证：撤掉修复 → 必须变红 →
   逐字节还原 → 必须变绿，并用 cmp 确认还原。
5. 只提交，不推送。提交信息用 `feat(<编号>): <一句话>` 或 `fix(<编号>): <一句话>`，
   正文写清改了什么、旧行为、新行为、验证结果。
6. 把结果追加到任务文件末尾的「结果回写区」，不要新建文件、不要覆盖已有内容。
   必须包含：提交 SHA、改动文件清单、实际命令与输出摘要（PASS/FAIL 计数与日志路径）、
   变异验证（撤掉什么、变红几条、还原后 cmp 是否一致）、没做/没验的东西、
   你认为的剩余风险。
7. 回复我时只说三件事：任务编号与标题；提交 SHA；有没有验收判据没达成（有就说哪条）。

规则：
- 不要开子代理，你自己做完。
- 不要问"要不要继续"，按任务文件做到完为止。
- 任务文件里的要求与仓库现状不符（文件不存在、接口改名）时，停下并在回写区写清
  阻塞原因，不要猜。
- 不要碰任务文件「边界」之外的任何文件；边界外的只读不写。
- 临时脚本写进 .tmp/ 再执行，不要写内联的一行命令。
```

---

## 为什么这样写

- **只改一个路径**：`tasks/XXXX.md`。其余固定，避免每次派活措辞漂移。
- 第 6 步强制回写：你看结果时不用翻对话记录，直接读任务文件末尾。
- 第 7 步只要三件事：避免执行对话用长篇总结掩盖「某条判据没达成」。
- 「不要扩大范围」前置：执行对话最容易在"顺手优化"上越界。
- 「不开子代理」：避免同一个任务里再分叉出多个改动者，互相踩文件。
- 冲突以台账为准：台账是本项目唯一的规则来源，任务文件只是它的派生物。
