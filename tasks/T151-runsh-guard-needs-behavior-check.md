# T151 — `run.sh` 守卫要加**动态判据**：静态检查抓形状，抓不住变体

**Status**：`ready-for-agent`
**Category**：P0 测试基础设施
**提出者**：总控（office）—— 它指出 T145 的静态守卫能被变体绕过
**写卡时间**：2026-10-24 21:55。**下面前提我都实测过。**

## 一、T145 的静态守卫守得住什么

```bash
# t145-runsh-path-smoke 第 [1] 条
FAIL ★ 没有 run.sh 在 `cd` 之后仍用 `dirname "$0"`
```

**它抓的是这个形状：**

```bash
cd "$(dirname "$0")/../.."
source "$(dirname "$0")/../lib/esbuild-path.sh"   # ← cd 之后还用 $0
```

**全仓已修 284 套，剩 1 个**（`o4-docs-close-smoke`，Office 线在途）。

## 二、但它抓不住这**四种**变体（我实测的）

```bash
# 变体 A：不带引号
cd $(dirname $0)/../..
source $(dirname $0)/../lib/esbuild-path.sh

# 变体 B：中转变量
SELF=$0
cd "$(dirname "$SELF")/../.."
source "$(dirname "$SELF")/../lib/esbuild-path.sh"

# 变体 C：BASH_SOURCE
cd "$(dirname "${BASH_SOURCE[0]}")/../.."
source "$(dirname "${BASH_SOURCE[0]}")/../lib/esbuild-path.sh"

# 变体 D：参数展开（Office 总控补的，我原来没列）
cd "$(dirname "$0")/../.."
source "${0%/*}/../lib/esbuild-path.sh"
```

**四个文件跑现有判据（「cd 之后还出现 `dirname "$0"`」）—— 全部 0 违规。**

**⚠️ 注意判据的正确写法**：不是「整个文件里 grep `dirname "$0"`」，
而是「**`cd` 之后的部分**里 grep」。因为正确的写法里 `$0` 也出现（在 `cd` 那行之前）。

```bash
# ❌ 这个会误报正确写法
grep -c 'dirname "\$0"' file.sh     # → 1（那行在 cd 之前，合法）

# ✅ 判的是「cd 之后还用它」
```

**而变体 B、C、D 的 bug 都是真的** —— `SELF`、`BASH_SOURCE`、`${0%/*}` 在 `cd` 之后
**仍然基于调用者给的相对路径**，从仓库根调用一样拼错。

## 三、动态判据的设计（Office 总控的建议）

> **静态检查抓形状，动态检查抓行为。**

### 做法

**对每个 `run.sh`，从仓库根调用一次，断言它不因为路径问题失败。**

**⚠️ 但 611 套全跑一遍要几十分钟**（T145 实测：每套 10–60 秒）。**不能进 CI。**

### 所以设计成「解析版 + 全量版」两档

#### 解析版（default）：**不起 bash 进程，纯文本 + 路径运算**

**⚠️ 我实测了「起 611 个 bash 进程只跑两行」这个方案：20 次 1.6 秒 → 611 次约 49 秒。
对 CI 太慢。**

**更快的做法：不执行，而是「模拟 `$0`」。**

```python
# 对每个 run.sh：
#   1. 抽出所有「定义变量」的行（SELF=$0 / HERE=... / 直接使用）
#   2. 抽出所有 cd / source 行
#   3. 按 bash 的语义顺序模拟：从仓库根起，$0 = "apps/desktop/scripts/<name>/run.sh"
#   4. 检查每一步 cd / source 的目标路径是否存在
```

**判据**：**「从仓库根调用时，每个 `cd` 和 `source` 的目标路径都存在」。**

**这是纯字符串运算 + `os.path.exists`，611 个文件应该是毫秒级。**

**⚠️ 它仍然是「模拟」，不是「真跑」。** 所以它覆盖的是「路径能不能解析」，
不覆盖「bash 的引号/变量展开语义」。

**要做对，模拟器必须支持：**

| 写法 | 解析 |
|---|---|
| `$0` | → `apps/desktop/scripts/<name>/run.sh`（调用者给的相对路径） |
| `SELF=$0` 然后 `$SELF` | → 同上（**变量追踪**） |
| `${BASH_SOURCE[0]}` | → **同在 `cd` 之后仍失效**（变体 C 的 bug） |
| **`${0%/*}` / `${0##*/}`** | → **参数展开，不是 `dirname` 命令**（变体 D，Office 总控补的） |
| `$(dirname ...)` | → 取父目录 |
| `"$VAR"` / `$VAR` | → 引号不影响路径解析，但要能剥离 |

### ⚠️ 卡上的措辞要求（Office 总控的原话）

> **明写「静态档抓 N 种已知拼写，不是穷举；穷举由 `--deep` 承担」。**

**这是「没有假装守住」的标准** —— 像 M 在 T128 写的
「它是正则匹配元素标签，**抓的是形状不是语义**」。

**⚠️ 如果模拟器做不到变量追踪或参数展开，必须在输出里说明，不能静默缩小覆盖。**

**具体做法**：静态档的输出里要有一行，形如：

```
静态检查：抓 4 种已知拼写（$0 / SELF 中转 / BASH_SOURCE / ${0%/*}），不是穷举。
穷举请跑 --deep。
```

**这一行本身就是判据的一部分** —— 有人加了一种新拼写而没加进模拟器，
至少读者知道「这里只覆盖 N 种」。

#### 全量版（`--deep`，几十秒到几十分钟）：真跑

**⚠️ 判据不能是 `rc == 0`，也不能是 `rc != 127`。**

**Office 总控实测出来的反例**：它从仓库根真跑 `o0` / `o3`，两个都是 **`rc=124`**：

```
124 是 `timeout 20` 打的超时，不是路径错。
它们正常跑需要几分钟（真 Electron）。
```

**所以 `rc != 127` 会把「超时」当成功。**

**正确的判据是看 stderr 的内容：**

```bash
# ⚠️ 但不能直接全文 grep —— 见下面 §边界
! grep -qE "No such file or directory|command not found" "$stderr"
```

**⚠️ 这条有个误报源：套件自己也可能输出这句话。**

比如某个套件在测「文件不存在时给什么错」，它的 `PASS`/`FAIL` 行里就带着
`No such file or directory` —— **判据会把它判红。**

**实测现状（2026-10-24 21:58）：全仓 0 套自己输出这句话。但这是「今天没有」，不是「永远不会」。**

**Office 总控给的做法**：

| 做法 | 说明 |
|---|---|
| **只看前 5 行**（推荐） | 脚本自身挂掉时，错误在开头；套件的业务输出在后面 |
| 匹配行首无缩进 | bash 自己打的错误通常不在缩进块里 |
| 排除含 `PASS`/`FAIL`/`ok `/`⚠️` 前缀的行 | 套件输出通常带这些前缀 |

**⚠️ 如果 `--deep` 出现误报，先查这里。**

**rc 的完整含义表**（写进卡里，免得下一个人只看 127）：

| rc | 含义 | 算失败吗 |
|---|---|---|
| `0` | 成功 | 否 |
| `1` | 套件业务失败 | **不算本判据的失败**（可能是别的线在途） |
| `2` | 用法错 | 不算本判据 |
| `124` | **`timeout` 超时** | **不算** —— 它可能只是跑得久 |
| `127` | **命令找不到** | **算** |
| — | **stderr 含 `No such file or directory`** | **算**（这是路径 bug 的直接特征） |

### 覆盖性断言（必须）

**`bash -c` 那一步如果一条都解析不到（比如正则失效），廉价版会全绿而什么都没验。**

**所以要有一条断言证明它真的跑了 611 次**，不是跑了 0 次。

**这是 CLAUDE.md 第八条第 8 种形态**：「被测代码的分支一次没跑，但套件全绿」。

## 四、变异

| # | 变异 | 预期红 |
|---|---|---|
| M-1 | 造一个变体 A（不带引号）的 run.sh | 1（新判据） |
| M-2 | 造一个变体 B（`SELF=$0` 中转） | 1 |
| M-3 | 造一个变体 C（`BASH_SOURCE`） | 1 |
| **M-4** | **造一个变体 D（`${0%/*}`）** | **1** |
| **M-5** | **负控**：正确形状（`HERE=$(cd "$(dirname "$0")" && pwd)` 再 `cd "$HERE/../.."`） | **0** |
| **M-6** | **负控**：`cd` 之后用 `$HERE` | **0** |
| **M-7** | **负控**：`cd` 之后用相对 cd 位置的路径（`o1` 的写法：`source "./scripts/lib/..."`） | **0** |

**⚠️ M-1~M-4 必须真的让新判据红。** 如果只让旧判据红，那说明新判据没生效
（旧判据对这四个变体本来就不红 —— 我上面实测过）。

**⚠️ M-5~M-7 是三种不同的正确写法**，都必须绿：

| 写法 | 为什么对 |
|---|---|
| `HERE=$(cd "$(dirname "$0")" && pwd)` + `cd "$HERE/../.."` | 先算绝对路径再 cd（**推荐**） |
| `cd` 之后用 `$HERE` | 同上 |
| `cd` 之后用相对 **cd 后位置**的路径（`o1` 的写法） | 相对 cd **之后**的 cwd，也能解析 |

**这三种都是真的正确** —— Office 总控实测确认了 `o0` / `o1` / `o3` 都是安全的。
**判据不能把它们判红，否则会逼人改本来对的代码。**

## 五、验收

1. **变体 A / B / C 三种都能被抓到**（旧判据抓不到，新判据必须抓到）。
2. **正确形状不红**（M-4 / M-5 负控）。
3. **覆盖性断言存在**，且证明了它真的扫了 611 个 `run.sh`。
4. **廉价版默认跑几秒内**（不是几十分钟）。
5. **不回归**：T145 的 8 条断言全绿（除了 `o4-docs-close-smoke` 那条 —— 那是别人在途）。

## 附：这条判据的通用教训

**T145 的静态判据是对的，但它只能证明「这一种形状不存在」。**

**而「全仓 0 违规」这个结论，它覆盖的是「所有 `dirname "$0"` 的写法」，不是「所有会拼错路径的写法」。**

**Office 总控的原话值得记：**

> **静态检查抓形状，动态检查抓行为。**
> **你今天修的 284 套如果只过静态检查，下次有人写个变体还是能绕过去。**

**这和 CLAUDE.md 第三十条（「跑了一个 grep」是样本，「穷举了所有写法」才是清点）同族** ——
**只不过这次「所有写法」是无限集，所以只能靠行为判据兜底。**
