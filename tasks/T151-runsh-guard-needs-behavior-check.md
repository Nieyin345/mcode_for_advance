# T151 — `run.sh` 守卫要加**动态判据**：静态检查抓形状，抓不住变体

**Status**：`ready-for-agent`
**Category**：P0 测试基础设施
**提出者**：总控（office）—— 它指出 T145 的静态守卫能被变体绕过
**写卡时间**：2026-10-24 21:55。**下面前提我都实测过。**

## 一、T145 的静态守卫守得住什么

```bash
# t145-runsh-path-smoke 第 [1] 条
FAIL ★ 没有 run.sh 在 `cd` 之后仍用 `dirname "$0"`
```

**它抓的是这个形状：**

```bash
cd "$(dirname "$0")/../.."
source "$(dirname "$0")/../lib/esbuild-path.sh"   # ← cd 之后还用 $0
```

**全仓已修 284 套，剩 1 个**（`o4-docs-close-smoke`，Office 线在途）。

## 二、但它抓不住这三种变体（我实测的）

```bash
# 变体 A：不带引号
cd $(dirname $0)/../..
source $(dirname $0)/../lib/esbuild-path.sh

# 变体 B：中转变量
SELF=$0
cd "$(dirname "$SELF")/../.."
source "$(dirname "$SELF")/../lib/esbuild-path.sh"

# 变体 C：BASH_SOURCE
cd "$(dirname "${BASH_SOURCE[0]}")/../.."
source "$(dirname "${BASH_SOURCE[0]}")/../lib/esbuild-path.sh"
```

**三个文件跑现有判据（`grep 'dirname "\$0"'`）匹配数全是 0。**

**而且变体 B、C 的 bug 是真的** —— `SELF=$0` 和 `${BASH_SOURCE[0]}` 在 `cd` 之后**仍然是调用者给的相对路径**，
从仓库根调用一样拼错。

**所以「全仓 0 违规」这个结论只覆盖一种形状。**

## 三、动态判据的设计（Office 总控的建议）

> **静态检查抓形状，动态检查抓行为。**

### 做法

**对每个 `run.sh`，从仓库根调用一次，断言它不因为路径问题失败。**

**⚠️ 但 611 套全跑一遍要几十分钟**（T145 实测：每套 10–60 秒）。**不能进 CI。**

### 所以设计成「解析版 + 全量版」两档

#### 解析版（default）：**不起 bash 进程，纯文本 + 路径运算**

**⚠️ 我实测了「起 611 个 bash 进程只跑两行」这个方案：20 次 1.6 秒 → 611 次约 49 秒。
对 CI 太慢。**

**更快的做法：不执行，而是「模拟 `$0`」。**

```python
# 对每个 run.sh：
#   1. 抽出所有「定义变量」的行（SELF=$0 / HERE=... / 直接使用）
#   2. 抽出所有 cd / source 行
#   3. 按 bash 的语义顺序模拟：从仓库根起，$0 = "apps/desktop/scripts/<name>/run.sh"
#   4. 检查每一步 cd / source 的目标路径是否存在
```

**判据**：**「从仓库根调用时，每个 `cd` 和 `source` 的目标路径都存在」。**

**这是纯字符串运算 + `os.path.exists`，611 个文件应该是毫秒级。**

**⚠️ 它仍然是「模拟」，不是「真跑」。** 所以它覆盖的是「路径能不能解析」，
不覆盖「bash 的引号/变量展开语义」。**但后者正是变体 A/B/C 的区别所在。**

**要做对，模拟器必须支持：**

| 写法 | 解析 |
|---|---|
| `$0` | → `apps/desktop/scripts/<name>/run.sh`（调用者给的相对路径） |
| `SELF=$0` 然后 `$SELF` | → 同上（**变量追踪**） |
| `${BASH_SOURCE[0]}` | → **同在 `cd` 之后仍失效**（这就是变体 C 的 bug） |
| `$(dirname ...)` | → 取父目录 |
| `"$VAR"` / `$VAR` | → 引号不影响路径解析，但要能剥离 |

**⚠️ 如果模拟器做不到变量追踪，那它只能抓直接写 `$0` 的。**
**这种情况下必须诚实标注它的边界**（像 M 在 T128 做的：「抓的是形状不是语义」）。

#### 全量版（`--deep`，几十秒到几十分钟）：真跑

**判据不是 `rc == 0`**（很多套件本来就可能因为别的线在途而红），**而是**：

```bash
# rc == 127 = 命令找不到 = 套件根本没起来
# stderr 含 "No such file or directory" = 路径问题
[[ $rc -ne 127 ]] && ! grep -q "No such file or directory" "$stderr"
```

**⚠️ 这个判据要能区分「路径错」和「套件业务失败」** —— 后者不算。

### 覆盖性断言（必须）

**`bash -c` 那一步如果一条都解析不到（比如正则失效），廉价版会全绿而什么都没验。**

**所以要有一条断言证明它真的跑了 611 次**，不是跑了 0 次。

**这是 CLAUDE.md 第八条第 8 种形态**：「被测代码的分支一次没跑，但套件全绿」。

## 附：这条判据的通用教训

**T145 的静态判据是对的，但它只能证明「这一种形状不存在」。**

**而「全仓 0 违规」这个结论，它覆盖的是「所有 `dirname "$0"` 的写法」，不是「所有会拼错路径的写法」。**

**Office 总控的原话值得记：**

> **静态检查抓形状，动态检查抓行为。**
> **你今天修的 284 套如果只过静态检查，下次有人写个变体还是能绕过去。**

**这和 CLAUDE.md 第三十条（「跑了一个 grep」是样本，「穷举了所有写法」才是清点）同族** ——
**只不过这次「所有写法」是无限集，所以只能靠行为判据兜底。**
