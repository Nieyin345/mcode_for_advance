## 背景：这是今天完全没碰过的一条主线

`docs/planning/mcode-product-roadmap.md` §3：

> **任务是一级对象，不依附聊天。** 一个任务有稳定 ID、目标、依赖、审批、状态、日志、检查点、产物、验收证据，
> **可以由聊天、工作流、自动化和多个 Agent 关联或推进。**

§5「首阶段验收」的核心闭环：

> **任务中心能追踪状态、失败、审批、产物与证据。**
> **用户能完成、返修并重新验收。**

## 任务

### 一、任务对象存在吗

```bash
grep -rn "interface Task\b\|type Task\b" packages/contracts/src/ | head
grep -rn "taskId\|task_id" apps/desktop/src/main/store/ | head
```

**判断**：
- 有**真正的一级对象**（有 ID、状态、产物、证据、能独立于聊天存在）？
- 还是只有**聊天消息的一个字段**？

**要区分这两种**：
- 「消息有 `taskId` 字段」 ≠ 「任务是一级对象」；
- 一级对象意味着：**能列出所有任务、能按任务查产物、任务能跨会话存活**。

### 三、返修闭环

> **用户能完成、返修并重新验收。**

**查**：
- 失败的任务能不能**重跑**？
- 验收不通过的能不能**退回**？
- **返修的历史**（第几次修、每次改了什么）能查到吗？
