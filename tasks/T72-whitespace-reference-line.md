## 一、措辞：把「期望 ≥ X%」改成「参考线」

### 现在的消息

```ts
message: `第 ${i + 1} 页内容只铺到画布高度的 ${(ratio * 100).toFixed(0)}%（${type} 页期望 ≥ ${(threshold * 100).toFixed(0)}%）：下半部分大面积留白。规范第 3 节要求「Fill the page」。`,
```

### 为什么这是问题（不只是文案）

**「期望 ≥ 80%」读起来是一条硬指标。** 模型看到它，最省力的做法是**把元素往下拉长去凑数** —— 于是它会把一个本来只是「稍微松一点」的页面，改成一个被拉伸变形、比例失调的页面。

这正好是用户抱怨的「又烂又丑」的另一个来源：**为了满足一个数字而破坏设计**。

T69 找出来的 KPI 页就是这个风险的具体形态：**83.3%，离 80% 只有 3.3pt**。卡片高度减 24px 就会掉下去被报，而「更紧凑的 KPI 卡」是完全合理的设计。

### 改成什么样

**要求**（三条都要满足）：

1. **明确这是参考线，不是硬指标** —— 用「参考线」「明显低于」「若设计上确实需要留白，可以忽略」这类措辞；
2. **保留可操作信息** —— 仍要给出「现在 X%，参考线 Y%」，否则模型没法判断差多少；
3. **不要用「期望」「要求」「必须」** —— 这三个词是硬约束的语气。

**参考写法**（不要求逐字照抄，但要素要在）：

```ts
message: `第 ${i + 1} 页内容底边只到画布高度的 ${(ratio * 100).toFixed(0)}%（${type} 页参考线约 ${(threshold * 100).toFixed(0)}%）：下半部分留白较多。若版面是有意的留白设计可忽略；否则考虑把内容铺开一些（规范第 3 节「Fill the page」）。`,
```

### 硬要求：**新措辞必须有断言守着**

改措辞不是改注释——**模型看到的就是这行字**。所以：

```ts
check("★ 留白消息是「参考线」语气，不是硬指标",
  finding.message.includes("参考线") &&
  !finding.message.includes("期望") &&
  !finding.message.includes("必须"),
  { message: finding.message });
```

**负面断言（`!includes("期望")` / `!includes("必须")`）必须配一条正控**：证明这个断言能看见消息确实变了 —— 见第二节的变异。

## 二、阈值：字面量提成命名常量，注释附实测出处

### 现在

```ts
const threshold = type === "cover" || type === "closing" ? 0.55 : 0.8;
```

**这是本仓库「注释即事实」规矩的反面样本**（CLAUDE.md 规矩七）：数字有出处，但**出处没写在数字旁边**——它在函数头注释里，离实际取值 20 多行。

### 改成什么样

```ts
/**
 * 留白判据的**参考线**（不是硬指标 —— 见 `checkWhitespace` 的消息措辞）。
 *
 * 数值来自 T69 对 T62 那份 deck 的逐页实测（2026-10-23）：
 *
 *   封面 cover      1.000 ｜ 内容页 content 好 0.872 ｜ 空柱 0.667
 *   KPI  data       0.833 ｜ 收尾页 closing      0.653
 *
 * 取 0.80 的效果：好的内容页不报（余量 7.2pt）、空柱被报（余量 13.3pt）、
 * KPI 不报（**余量只有 3.3pt，这是最脆弱的一条**）。
 *
 * ⚠️ **不要在没有新样本的情况下调这两个数。** T69 试过收紧到 0.85 —— 直接误伤
 * KPI 页。样本只有 1 份 deck 的 5 个页面，在 5 个点上调参就是过拟合。
 */
const WHITESPACE_REFERENCE_LINE: Record<"loose" | "tight", number> = {
  /** cover / closing：收尾页本来就该留白，65.3% 是设计意图。 */
  loose: 0.55,
  /** content / data：空柱子 66.7% 必须报，好的内容页 87.2% 不能报。 */
  tight: 0.8,
};
```

（命名与结构你自己定，但**必须**：① 是命名常量；② 注释里有实测数字与「不要调」的理由；③ `RECOMMENDED_FIXES` / `ruleDescriptions` 之类的说明文本也同步更新。）

## 三、`RULE_DESCRIPTIONS` 那行也要改

`deckPatternCheck.ts:341`：

```ts
"layout.whitespace": "内容底边占画布高（content/data ≥ 80%，cover/closing ≥ 55%）",
```

`≥` 同样是硬约束语气。改成「参考线约」。**这行也是模型会读到的。**
