### ① 打地鼠

用「三根空柱子」造 BAD，按判据给的提示改：

| | findings | 元素面积占画布 |
|---|---|---|
| 改前 | `card-whitespace` × 3 | **63%** |

**两条判据方向相反**：

- `card-whitespace`：卡片别高于内容 → **卡片变矮**

**卡变矮之后页面当然更空。而提示没说「同时补内容」。**

### ② `palette.rainbow` 没有色相判断（**最严重**）

F 的 GOOD deck（深色封面 + 柱状图 + 同色阶梯）被报 **error**。

那三根柱子是 `#1F3A5F` / `#3E6E9E` / `#6FA3D2` —— **同一蓝色的深浅阶梯，数据可视化的标准做法。**

源码 `deckPatternCheck.ts:171-183`：

```ts
const colors = new Set<string>();
...
colors.add(f);          // ← 按色值字符串去重

```

`isNeutral` 只判「接近灰/极亮/极暗」，**完全没有色相判断**。

**后果：做得好的数据可视化 deck 会被报最高严重度错误，模型会去「修」它。**

### ③ `cover` 豁免形同虚设

```ts
const type = page.type ?? "content";
const threshold = type === "cover" || type === "closing" ? loose : tight;
```

**豁免只认 `page.type === "cover"`。而模型写 spec 时通常不填 `type`** → 默认 `"content"` → 走 tight → **封面必报**。

**豁免在等一个模型不会填的字段。**

## 任务

### 一、`palette.rainbow` 按色相聚类

**把「同一色相不同明度」算作一个色。**

**实现要求**：

1. 把 hex 转 HSL（或 HSV）；
2. **色相接近的归为一组**（阈值你定，写进注释并论证）；
3. 中性色（低饱和度）仍然排除；
4. **同一组的多个明度算 1 个色**；
5. 组数 > 2 才报。

**关键正控/负控**：

| 用例 | 期望 |
|---|---|
| `#1F3A5F` / `#3E6E9E` / `#6FA3D2`（同色相三明度） | **不报** |
| `#FF0000` / `#00FF00` / `#0000FF`（三色相） | **报** |
| 两个强调色 + 一个同色相明度 | **不报**（仍是 2 组） |

**阈值论证**：色相差多少度算「同色相」？**给出理由**（不要拍一个数字）。

### 二、`cover` 豁免改成几何判断

**选一个并论证。** 我倾向「几何特征」，因为它不依赖模型填字段。

### 三、打地鼠：两条提示要联动

**`card-whitespace` 报出时，如果页面整体也偏空，消息里要同时说「补内容而不是只缩卡片」。**

**最简单的实现**：`card-whitespace` 的 message 加一句：

**或者**：当页面同时满足两个条件时，**合并成一条** finding。

**你判断哪种更好，并说明理由。**

## 结果回写（2026-10-24）

### 一、色相阈值：30°，依据是实测空档

在一组样本上量了「最大两两色相跨度」：

| 样本 | 最大跨度 | 该不该报 |
|---|---|---|
| 同一蓝色三档明度 `#1F3A5F`/`#3E6E9E`/`#6FA3D2` | **6.2°** | 不报 |
| 同色相、跨很大明度 `#0B1A2B`/`#2E5C8A`/`#A8D0F0` | **5.2°** | 不报 |
| 三色相卡片 `#FF3355`/`#33FF55`/`#3355FF` | **140°** | 报 |
| 纯彩虹 `#FF0000`/`#00FF00`/`#0000FF` | **120°** | 报 |

**6.2° 与 120° 之间是约 20 倍空档**，阈值落在任何位置都能分开。取 30° 的理由：

- 是「同色相」实测上界的 **约 5 倍余量**（设计系统的 50–900 阶梯在 HSL 里色相漂移通常 < 15°）；
- 是真彩虹下界的 **1/4**；
- 30° 也是常见的「相邻色相」步长（HSL 色轮表常按 30° 一档）。

**局限**（写进注释了）：HSL 的色相**不是感知均匀的**——同样 30° 在黄绿区差很多、在蓝紫区几乎看不出。要更准得用 OKLCH，但本判据只需要「同一色阶 vs 真彩虹」这一档区分，30° 足够。

**聚类方式**：单链（single-linkage）——依次并入第一个「与组内任一成员距离 ≤ 阈值」的组。一条连续色阶的相邻两档差远小于整体跨度，单链能整条收进一组；彩虹三色彼此都超阈值，分三组。

### 二、cover 判据：**必须有满版底板**

**第一版判据是错的，`t65` 当场抓到。** 我原先写「内容元素 ≤ 3 个就算封面」：

```
TypeError: Cannot read properties of undefined (reading 'message')
  at ... .find(f => f.rule === "layout.whitespace").message
```

`t65` 那个 `thin` 用例是 `type: "content"`、只有「标题 + 一张卡」两个元素、底边 60%、右下大片空白 —— **那是该报的**，却被「元素少」的判据当成封面放过了（loose 55% < 60%）。

**「元素少」不等于「是封面」**：一个做得差的内容页也很稀疏。封面真正的特征是**有一块铺满画布的底板**。

最终判据：**有满版底（`isFullBleed`）且底色上的内容元素 ≤ 4 个**。没有满版底的稀疏页面按内容页走紧阈值。

同时保留 `page.type` 的显式声明（写了就用），**两者取「更宽松」**。

### 三、打地鼠：message 加联动提示，不合并成一条

**选 message 联动**，理由：

1. **合并会丢信息**——「卡片内空」和「整页空」是两个不同位置的问题，合并后模型不知道该改哪儿；
2. **`card-whitespace` 是每张卡一条**（T83 的硬要求：不吞第二张），合并会打乱这个契约；
3. 联动提示里可以带上**预测数字**，比一条合并的结论更有可操作性。

**第一版判据也是错的，实测发现。** 我原先用「当前页是否也空」（`pageBottomRatio < tight`）决定要不要提示。实测 BAD 页内容底边是 **89%**（三张高卡撑住了），`layout.whitespace` **根本不报** —— 但模型照「缩短卡片」改完，底边掉到 31%，那一刻才出现。

**所以打地鼠不是「两条同时报」，是「按 A 改 → 产生 B」**。判据改成问「**把卡缩到内容高度之后，整页会不会变空**」（`predictedBottomRatioAfterShrinkingCards`）。

现在提示长这样：

```
⚠️ **先补内容再缩卡**：把这张卡缩到内容高度后，整页内容底边会掉到约 31%
（留白参考线 80%），届时会触发「留白过多」。请在卡内补足内容（要点分栏、放图表/数据），
而不是只把卡片压扁。
```

### 四、**一个计划外但更严重的发现：`isNeutral` 把纯色全判成「中性」**

补 t65 断言时发现「三色相不报」。查下来是**既有缺陷**（HEAD 就有，不是我引入的）：

```ts
return max - min < 24 || max > 238 || max < 30;  // ← max > 238
```

`max > 238` 本意是排除「近白背景」，但**任何有一个通道接近满值的鲜艳色**都会被排除：

| 颜色 | max | 旧判据 | 实际 |
|---|---|---|---|
| `#FF3355` | 255 | **中性（排除）** | 纯红 |
| `#33FF55` | 255 | **中性（排除）** | 纯绿 |
| `#3355FF` | 255 | **中性（排除）** | 纯蓝 |

**所以真正的彩虹卡片从来不会被报，而柔和的同色系阶梯反而会报。判据是反的。**

`t65` 原来的负控用 `#E23B3B`/`#2ECC71`/`#9B59B6` —— 它们 max ≤ 238，**从未碰到这个分支**。

**修法**：「近白」要看**整体亮度**（三通道都高），不是最大通道高：
```ts
return max - min < 24 || min > 238 || max < 30;  // 接近灰 / 三通道都极亮(白) / 极暗
```
