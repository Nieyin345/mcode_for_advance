## 跨任务请求、未完成与风险

**OBS-M14-01 · 会话结束/断线没有任何清理钩子（P2，需要跨任务配合，本轮未改）**
`agentMcpTools()` 全仓只有一个调用点（`mcp/webToolHost.ts:196`，宿主构造时调一次），
因此 `createAgentProcessSessions()` / `createAgentSearchSessions()` / `createAgentRemoteSshManager()`
产生的三个管理器是**进程级单例、按 `ownerSessionId` 分桶**，而三者都**没有暴露按 owner 释放的接口**，
全仓也检索不到任何 dispose/cleanup 调用点。后果：
- 持久进程：对话删掉/扩展断开后仍活到自己的 `timeoutMs`（默认 10 分钟，上限 60 分钟）；
- 搜索会话：靠 `COMPLETED_TTL_MS`(10 分钟) 才回收，且只在下一次 `start`/`list` 被动触发；
- **SSH 连接最严重**：`agentRemoteSsh` 的 `entries` 永不清除，而连接带 keepalive + 指数退避**自动重连**，
  没有 `intentionalClose` 就会一直重连下去——对话早就没了，机器还在敲远端。
修不了的原因：三个管理器本身在 M14 写范围内，但**触发点**在会话收场那一侧
（`RuntimeManager` / `providers/**`，属 M03/M06 一线，且 `webToolHost` 的 `gateFor` 语义由那边提供）。
**跨任务请求**：请 RuntimeManager 的所有者（协调者按 `M/providers/**` 与运行时归属指派，疑似 M03/M06，必要时留给 M36 统一接线）
在会话收场处提供一个 `disposeAgentSession(sessionId)` 调用点；接口那半边我这边随时可以补上，本轮不先落空实现（避免留死代码）。

**OBS-M14-02 · `MCP_LIST` 的探测回填漏判 `enabled`（P3，本轮未改，属本任务文件）**
`ipc/mcp.ts` 第一遍明确“只探已启用的行”（注释写了理由），但**第二遍回填**

于是一个曾经启用过、缓存里留着 `requiresAuth:true` 的 server 被**停用之后**仍会显示“待授权”徽章。
影响仅限面板显示，不影响任何注入行为。**为什么不在本轮改**：它只能从 db 绑定的 handler 打进去，
