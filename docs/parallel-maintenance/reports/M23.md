## 发现与修复
### BUG-M23-01（P1，已修）：主进程/手机端发起的中断让桌面输入框永久锁死
- **复现**：会话正在跑；不点桌面停止键，直接注入 `turn.done{reason:"interrupted"}`（这正是 `RuntimeManager.enforceBudget` 预算触顶 → `handle.interrupt()`、`mobileRpc` 手机点停 → `runtimeManager.interrupt`、工作流取消 `runner.ts` 的收口事件在桌面端的到达形态）。旧代码：`runningBySession[sid]` 仍为 `true`，`turnMeta.endedAt` 未冻结，`runningTurnStartedAt` 未清。
- **影响**：输入框显示“运行中”且锁死、「开始·用时」一直跳、这一轮不落库（终态持久化跳过）、`drainPromptQueueIfIdle` 不触发，直到用户重启或换会话重拉。
- **根因**：`ingestEvent` 中 `if (turn.done && reason==="interrupted" && !interruptedBySession[sid]) return;`——哨兵只由本端 `interrupt()` 设置，“哨兵未立”并不能证明事件陈旧。
- **最小修复**（仅 `sessionStore.ts`，+32/−8 含注释）：新增模块级 `pendingInterruptDone: Set<string>`；`interrupt()` 发 IPC 前登记“欠一条中断收口”；任何 `turn.done` 到达即销账；只有 **欠账存在且哨兵已被新一轮清掉** 时才丢弃 interrupted 收口。原 stop→edit→resend 竞态行为不变（套件 [2] 在旧代码上即通过、新代码上仍通过）。
- **残余（已记录、未改）**：若本端停止后 SDK 从未发出收口、用户立刻重发、且新一轮又被外部中断，则该次外部收口会被误丢一次；随后任何 turn.done 都会清账，不会持续。需要 provider 侧保证中断必有收口才能根除，不在本任务写集。
