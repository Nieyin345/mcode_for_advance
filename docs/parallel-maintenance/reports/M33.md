## 2. 本次修复的问题(全部先有真红测试)

### ① `attached` 模式收到目录 → 造出"指向从未创建的文件"的死条目
`fileImport.ts` attached 分支对目录用 `if (!isDir)` 静默跳过复制,`file_path` 却写上
`files/<id>-<名>`(从未创建)。`library.importGeneric` IPC 允许 `mode:"attached"` +
任意路径,真实入口可达;条目点开永远是「文件不存在(被移走了?)」。
**修**:目录一律按目录条目的唯一合法形态 linked 落(`effectiveMode`,与
`importAnyFiles` 的分派口径一致);顺带获得 linked 的按路径查重。

### ② `attached` 复制失败留"半截条目"(失败清理缺失)
先 upsert 拿 id、复制一抛只记 `errors`,刚建的行留在库里 —— 无文件、无归属、任何
界面入口都够不着。**修**:`filesDir()` 挪到 upsert 之前(落点建不出来就不留行);
复制/写路径失败时 `LibraryRepo.delete([item.id])` 后原样抛给 per-file catch。

### ③ 三处对分类 id 裸调 `CollectionRepo.assign` → 外键直接炸 / handler 半途报错
外键是**开着**的(红日志实测 `FOREIGN KEY constraint failed`):
- `notesImport.importNoteFiles` / `createNote`:条目已 upsert+落盘后 assign 抛,被
  报成"导入失败",库里却已多了半截条目;
- `ipc/library.ts LIBRARY_ADD_ITEMS`:条目已入库后 handler 整个 reject;
- `ipc/library.ts LIBRARY_IMPORT_GENERIC`:文件**已复制进库**后 handler reject。

**修**:三处统一走 `assignImportedToCollections`(先核对分类还在,失效 id 记警告
跳过;顺带获得"归类时从回收站摘出"语义)。`LIBRARY_IMPORT_GENERIC` 改为把
`collectionIds` 交给 `importGenericFiles` 本人(与 `LIBRARY_IMPORT_FILES` 同一套行为,
重复导入给回的旧条目也照样归入)。

### ④ 笔记导入失败后重试被自己卡死;重复导入丢分类、不给回条目
- 复制失败留下的半截行(同标题、无 md)被按标题查重判成"已存在" —— 一次失败后
  这篇笔记**永远进不来**且无报错。**修**:失败时删除半截行;查重只认**有 md 文件**的行。
- 同标题重复导入时 `skipped+1` 就完了 —— 选定分类被丢掉、`items` 空手而归。
  **修**:与 PDF 管线 `alreadyPresent` 同一口径:归入本次选定分类并给回已有条目。
