## 1. 本次直接修复(6 项)

### FIX-1 · MinerU 转录脚本 itemId 落点越界(M33 报告 §4-1 → M28 域,回访时仍未修)
`M/workflows/assets.ts` 的 `MINERU_PY.transcribe_one` 用**载荷里的** itemId 拼结果目录(`Path.cwd()/"mineru"/item_id`),载荷可被 code 节点/外部触发器喂入 —— `"../x"` 把结果目录写出 `mineru/`,`"../../x"` 写出工作目录。
**修**:itemId 只认单个路径分量(`/`、`\`、`.`、`..` 一律拒,人话报错)。
**红证据(修复前,HEAD 版实测)**:`scripts/maint-audit-smoke/red-old-mineru.mjs` 对 `git show HEAD:` 的旧脚本注入 `itemId="../逃逸x"` → `ESCAPED_DIR_CREATED: true`(目录真建到了 mineru/ 之外)且一路走到网络调用。
**绿**:`maint-audit-smoke` §1 —— 越界与 `..` 均在建目录**之前**被拒、不落任何目录;正常 itemId 照走且落点在 `mineru/` 之下(守门无误伤)。

### FIX-2 · `git:stage` 缺 `--`(M15 报告加固建议,桌面端同型)
`ipc/git.ts` 与 `mobile/mobileGitRpc.ts` 的 stage 直接 `git.add(filePaths)`:以 `-` 开头的文件名(如 `-f`)会被 git 当选项吃掉(`git add -f` 顺手暂存被 ignore 的文件)。unstage/diff 两条早就带 `--`,stage 漏了。**修**:`git.add(["--", ...filePaths])` ×2。验证:tsc + `ipc-parity-smoke`/`mobile-sync-smoke` 绿(无既有套件驱动真实 git add;属防御性收口,与相邻 handler 口径对齐)。

### FIX-3 · MCP 面板"停用后仍顶待授权徽章"(OBS-M14-02,M14 报告登记未修)
`ipc/mcp.ts` 探测回填第二遍漏判 `s.enabled` —— 曾启用过、缓存里留着 `requiresAuth:true` 的 server 停用后仍显示「待授权」。**修**:回填加 `!s.enabled` 短路,与第一遍"只探已启用的行"同一判据。验证:`mcp-ipc-smoke`、`maint-m14-smoke` 绿。(回填不看 `AUTH_PROBE_TTL_MS` 的次一级观察仍留,见 §3。)
