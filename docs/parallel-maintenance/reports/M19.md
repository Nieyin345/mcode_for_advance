## 发现与修复

### BUG-M19-01 · P1 批量名单更新短路导致漏报/重复通知

根因：`agents.some(...)` 内修改历史 Map，一旦前一个代理完成就短路，后续代理状态未记录。

复现：先发 a/b running，再发 a completed/b failed，再重放终态。旧实现显示 2 条而非 1 条；同批末尾新 running 代理随后完成又可能漏报；关闭偏好期间也会留下陈旧状态。

修复：用完整 for-of 遍历计算是否有完成边沿，始终记录全部代理，一批最多通知一次。

### BUG-M19-02 · P1 窗口焦点闸门错误地挡住状态观察

根因：窗口处于前台就提前 return，通知历史未接收完整 roster。

复现：前台开始→后台结束为 0 条（应 1）；后台开始→前台结束→后台重放为 1 条（应 0）。

修复：仅 subagent.update 的状态评估移到窗口闸门之前，其余通知评估仍在原位置；窗口聚焦时仍不展示 OS 通知，没有改变前台抑制策略。

### BUG-M19-03 · P2 把完整快照当增量合并

冻结事实：contracts/runtime.ts 的 SubagentUpdateEvent 明确 full current roster，host should replace, not merge；空数组表示没有活跃或最近完成任务。

复现：running → [] → 同 ID completed，旧状态仍触发通知；完整快照移除某 task 后该 task 的迟到终态同样误报。

修复：每次以新 Map 替换，空名单删除该 session 桶。无界遗留 session 的全面生命周期回收不是本次承诺，未在 turn.done 时一刀删除仍可能运行的后台任务。

三个修复只改 `apps/desktop/src/main/notifications/NotificationManager.ts` 两处局部逻辑，无导出/IPC/schema 变更，无新增依赖，无性能优化宣传。
