## 发现与修复
- **BUG-M13-01（P0，数据删除）：清单 version 被直接用作目录名。**
  - 根因：`pluginVersionOf` 只把非 `[A-Za-z0-9.+-]` 字符替换成 `-`，保留了 `.` 和 `..`。
  - 复现与影响：
    - 插件清单写 `"version": ".."` 时，`finalizePluginInstall` 的目标是 `plugins/<name>/..`，也就是 `PLUGINS_ROOT` 本身。随后把整个插件根目录改名为 backup 再删除，**所有已安装插件和市场克隆全部丢失**，安装本身还以 ENOENT 报错。
    - 写 `"."` 时，目标是插件自己的基目录，裁剪步骤随即删掉刚装好的全部内容（报“安装后清单解析失败”）。
    - 任何本地目录、zip 或市场来源的清单都能触发。
  - 修复：
    - `pluginManifest.ts`：只由点组成的版本号回退为 `0.0.0`。
    - `pluginManager.ts`：`finalizePluginInstall` 增加包含关系断言，目标必须正好位于 `plugins/<name>/` 下一层，而且目录名等于版本号，否则拒绝安装。
- **BUG-M13-02（P1，数据删除）：插件名 `marketplaces` 与内部市场目录冲突。**
  - 根因：`PLUGIN_NAME_RE` 允许这个名字。
  - 复现与影响：
    - 安装名为 `marketplaces`（或 `Marketplaces`，Windows 大小写不敏感）的插件时，单版本裁剪会删掉 `plugins/marketplaces/` 下所有市场克隆。
    - renderer 可调用的 `removePlugin("marketplaces")` 直接删除整个市场目录。
    - `setPluginEnabled("marketplaces")` 被接受，会把市场克隆当成插件根去投递技能。
  - 修复（`pluginManager.ts`）：新增 `isReservedPluginName`（不区分大小写），安装（finalize）、启用、卸载、`installedRootOf` 四处统一拒绝或忽略这个名字。没有修改 contracts 的正则，旧数据兼容不受影响。
- **性能优化**：无，本任务未做性能改动。
