## 检查范围与发现

检查了本任务允许范围内的 `main/lib/sessionFork.ts`、`sessionStart.ts`、`sessionSync.ts`、`sessionAgentProfile.ts`、`session/AutoArchiver.ts`、`claude/RuntimeManager.ts` 与 `claude/subagentStore.ts`；并核对会话侧栏分叉入口、M02 相关既有 smoke 的行为（仅只读）。没有使用真实模型、真实用户库或启动应用。

发现：`forkSession()` 用 `...source` 构造副本，却未重置瞬时 `status`。侧栏的分叉入口允许对具备分叉能力且已有 provider session id 的会话执行分叉，并不排除 `running` / `approving`。因此从活动会话复制出的新行会继承源会话的活动状态，但新副本没有对应的运行句柄或待处理审批，可能持续显示为运行中/等待审批，也会被自动归档排除。

## 修复

在 `main/lib/sessionFork.ts` 创建副本时显式设 `status: "idle"`。源会话状态及其活动运行时不受影响；新副本保留原有上下文/消息分叉语义，但不冒充拥有源会话的活动 turn 或审批。
