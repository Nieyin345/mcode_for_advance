## 发现与修复

### BUG-M10-01(P0):`git:worktreeRemove` 会递归删除**任意**调用方给定的目录

**症状**:`removeWorktree(repoPath, worktreePath)` 在 `worktreePath` 不是本仓库已注册工作树时,会跳过**全部**数据安全闸(脏检查、补丁导出、`git worktree remove`),直落函数末尾的
`rm(worktreePath, { recursive: true, force: true })`。而这条路径上没有任何东西证明这个目录是我们的:

- IPC 层 `ipc/git.ts` 的 `GIT_WORKTREE_REMOVE` **只校验 `repoPath`**(`findContainingProject`),`worktreePath` 原样透传 —— 这不是疏忽的偶然,是设计使然:工作树按设计住在所有项目根之外,项目级闸门根本管不到它;
- 于是一条陈旧的渲染端条目、一次改过 `worktree.root` 设置之后的残留、或者任何形态错误的调用,都会把一个**无关目录连同子树永久删掉** —— 而且是 `rm`,不是回收站。

这个 `rm` 本身是有正当理由的(Windows 上文件占用会让 `git worktree remove` 半途而废:注册信息已摘、目录还在,重跑会喊 "is not a working tree"),问题只在于它**缺一道"这是我们的地盘吗"的判断**。

**修复**(`lib/worktreeOps.ts`):在 `registered` 探测之后、进入删除流程之前加一道归属闸。"是我们的"= 三者之一:

1. git 里仍注册为本仓库的工作树;
2. 有会话行记着这个路径(覆盖**旧受管根**下创建、之后才改过设置的工作树 —— 自愈能力不能被闸门误杀);
3. 位于当前受管根之下。

三者都不满足 → 记 warn 并返回 `ok:false`,一个字节都不碰。包含判断复用共享实现 `lib/pathGuard.pathWithin`(Windows/macOS 大小写归一 + 分隔符感知前缀比较),不另起一份。

### BUG-M10-02(P1):`git:worktreeMergeBack` 会在无关仓库里静默 `git add -A && git commit`

**症状**:同一条没有校验的 `worktreePath`,在 `mergeBackWorktree` 里的第一件事就是"脏就自动提交":

```ts
const wtGit = (await loadSimpleGit())(worktreePath);
const probe = await worktreeDirty(wtGit);
if (probe.count > 0) { await commitAll(wtGit, message); }
```

指向一个无关仓库时,**用户在那边写了一半的东西会被直接 commit 掉**,随后它的历史还会被合进项目仓库。红灯实测:调用返回 `ok:false`(合并无关历史失败了),但对方仓库的 `git status --porcelain` 已经空了 —— 也就是说,用户看到的是一条报错,实际发生的是一次他没要求过的提交。报错还掩盖了破坏。

**修复**:加上与 remove 对称的归属闸 —— 合并回主仓库这件事,只对**本仓库确实注册过的工作树**有意义,所以直接要求它在 `git worktree list --porcelain` 里。探测失败时不拦(与 remove 的 `registered = true` 降级保持一致:路径合法时 merge-back 本身不具破坏性)。
