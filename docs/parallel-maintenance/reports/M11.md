## 发现与修复
### BUG-M11-01：回调抛错后遗留已绑定端口（P1，失败路径资源泄漏）
真实 server 绑定成功后 onBind 抛错，旧实现立即拒绝但 server.listening 仍为 true；禁用端口的同类异常也没有 close。调用者看到失败而端口/句柄仍活跃。
仅修改 main/lib/loopbackPort.ts：成功绑定后的 onBind 异常先等待本次 server.close 完成，再抛回原异常；不继续尝试分配。

### BUG-M11-02：绑定失败后遗留本次尝试的监听器（P2）
同步 listen 抛错遗留 error handler；异步 error 遗留 listening callback；已有真实 server 上 ERR_SERVER_ALREADY_LISTEN 也遗留 error handler。
命名 onListening，成功/失败均按函数身份清理本次 error/listening 回调；捕获同步 listen 异常并清理。不使用 removeAllListeners，不关闭调用前已有 server，不改变端口黑名单、5 次重试、回调 attempt 顺序或成功返回行为。
