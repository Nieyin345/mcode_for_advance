## 发现与修复

### BUG-M21-01(P0):提权执行的是一个**用户可写目录里的脚本文件**

`runElevated` 原先把安装脚本写成 `%TEMP%\mcode-onlyoffice\install.ps1`,再:

```
Start-Process -FilePath 'powershell.exe' -Verb RunAs -Wait -ArgumentList @(..., '-File', 'C:\Users\<user>\AppData\Local\Temp\mcode-onlyoffice\install.ps1')
```

`%TEMP%` 是**当前用户可写**的,而这个文件将以**管理员身份**被执行。任何以该用户身份运行的进程,只要在「用户点下『本机安装』」与「用户在 UAC 弹窗上点『是』」之间把这个文件换掉,就拿到了管理员权限 —— 而 UAC 弹窗恰好给了这个时间窗几秒到几十秒。

这在 Mcode 里不是理论风险:**这个产品的本职就是运行 AI Agent 生成的代码**,那些代码正是以当前用户身份跑的。也就是说,一个被诱导的 Agent 回合可以写好 `install.ps1` 静静等着,等用户自己去点那个安装按钮。UAC 弹窗上显示的还是 `powershell.exe`,用户看不出异常。

**修复**:脚本不再落盘,改为内联 `-EncodedCommand`(UTF-16LE base64)。没有文件,就没有可替换的窗口。附带收益:原先靠「写 UTF-8 BOM」绕开 PowerShell 5.1 按 ANSI 读 `.ps1` 的编码问题,`-EncodedCommand` 本身就是 UTF-16LE,这个坑自然消失(`writeFileUtf8Bom` 随之删除)。marker 与日志文件也改成一次性随机名 —— marker 是「脚本成功了吗」的唯一信号,固定名意味着可以提前放一个假的进去骗过校验。

### BUG-M21-02(P1):~1 GB 的安装器在提权执行前没有任何来源校验

安装包从网上下到用户可写的 `%TEMP%`,随后以管理员身份执行;复用缓存时只比对 `Content-Length`。同样地,一个大小凑对的文件被放在那儿就会被当成官方安装器**以管理员身份跑掉**。

**修复**:在提权脚本里,`Start-Process` 安装器**之前**先验 Authenticode:

```powershell
$sig = Get-AuthenticodeSignature -FilePath $exe
if ($sig.Status -ne 'Valid') { throw "installer signature is $($sig.Status), refusing to run it elevated" }
if ($sig.SignerCertificate.Subject -notmatch 'Ascensio|ONLYOFFICE') { throw "unexpected installer signer: $subject" }
```

验签在**提权上下文里**做,不在可被抢先的用户态做;顺序被测试钉死(签名检查的位置必须早于 `Start-Process -FilePath`)。

为了让这段以管理员身份执行的文本可被断言,脚本生成抽成了导出的纯函数 `buildElevationCommand()`。
