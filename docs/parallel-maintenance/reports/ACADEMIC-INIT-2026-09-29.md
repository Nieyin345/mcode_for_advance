## 结论：学术流程已由通用机制承载，但不是“零内置学术代码”

| 能力 | 实际承载及接线 | 验证边界 |

| 文献导入、DOI 下载 | 自定义资料库菜单 → 自动化触发器 → 工作流代码/代理节点 → 资料库导入。下载队列不再是独立原生专有入口。 | 输入 files/doi、空分类作为落点、载荷拍平、资料库回库有离线回归；真实下载需用户配置外部 MCP/账户。 |

仍然内置：默认工作流图和 prompt、首次自定义菜单种子、MinerU/导入脚本、资料库产物接收适配。这些是模板与连接层，并不等于学术能力已全部搬到外部插件。此次没有以“通用化”为名删除已有可用入口。

## 修复：首次学术菜单不再猜测绑定

原逻辑在找不到转录候选时退到第一条 event 自动化。记忆捕获等无关任务因此可能被挂到“转录”按钮上；多个同名候选以及已删除工作流遗留触发器也可能误绑。

现在只在**存在所属工作流且候选唯一、名称明确匹配**时预置；转录额外要求 event 触发器。无匹配或有歧义时使用已有缺失说明，不随便选第一个。

回归：旧实现 132/136，新增四条断言失败；修复后 136/136。仅改变首次种子的构建规则，**不覆写用户已经保存的自定义 UI 配置**。已有菜单如果曾被旧版本误绑，需在自定义 UI 设置中人工核对绑定。

## 新功能：用户定义的确定性初始化

### 使用

1. 打开 **设置 → 记忆与上下文 → 项目初始化**。
2. 新建方案，填写名称、说明、文件夹相对路径、文件正文以及项目记忆。
3. 保存后，聊天 `/` 菜单出现 `/init-名称`；例如用户将方案命名为“学术”就得到 `/init-学术`。“学习”“讨论”“会议”等没有写死或默认安装。
4. 在目标项目对话中选择命令，或单独输入完整命令；检查预览中的项目、实际工作目录、文件及记忆内容。
5. 确认执行。结果逐项显示已创建、跳过或失败。

### 行为与保护

- 按保存内容直接执行：**不请求模型、不运行 shell、不耗模型额度**。
- `/init-*` 是保留的本地命令前缀。未知名称、参数、技能、附件、会话忙碌等会明确拒绝，不掉入模型、排队或插话路径。旧 `/init` 的 AI 生成 AGENTS.md 行为不变。
- 文件目标由主进程根据发起会话解析：使用该会话 worktree，否则使用项目根目录。项目记忆始终归该会话的真实项目，不写全局记忆。
- 文件按 UTF-8 文本创建，不生成 Office/PDF 等二进制格式。文件夹补齐父目录；文件完整写好后以同目录原子 no-clobber 发布；记忆复用正式 memory store 的 create-only 保存、敏感内容检查及变更通知。
- 所有已存在的文件/记忆均跳过，不比较后覆盖；遇到类型冲突、越界路径、符号链接/联接等阻止计划。
- 预览不是写入；确认时重建计划并校验指纹。修改方案、改变目标或已有项状态后需重新预览。
- 每项目初始化执行锁；模板修改/删除使用 revision 防止陈旧写入；名称规范化后防重名。
- 部分失败逐项报告，已成功创建的项不回滚。可以修正原因后重新预览，成功项会被跳过。
- 取消保留手输命令；完成时只清理未被继续修改的原命令。切换对话不能沿用旧预览确认。
- 设置草稿保留到当前 renderer 生命周期；保存期间切走再返回，锁、方案身份与回执仍保持一致。陈旧读取不能替换新选择；显式放弃草稿才重新读取已保存版本。
- 修改记忆自动注入开关不是初始化的副作用。若用户关闭了注入，新记忆仍保存，但不会被强行自动携带。
- 桌面支持；Web API 明确异步拒绝，手机文件写入白名单保持原样，没有隐式扩权。

### 限额及技术边界

每方案最多 100 个显式目录、100 个文件、30 条记忆；含父目录的目录计划最多 500 个，路径最多 16 层。单正文最多 131,072 字符，总正文最多 1,048,576 字符（是字符计数，不是精确 UTF-8 MiB）。最多 200 个方案。没有新增依赖或单独数据库表，使用既有 SettingsRepo、Zod、React/Base UI 和 memory store。

文件原子发布依赖目标文件系统支持同目录硬链接；不支持或无权限时明确失败，不降级为覆盖写。祖先检查和复验不能承诺消除恶意本地进程同时替换目录的全部 OS 级 TOCTOU；也不承诺进程崩溃时整批操作事务回滚。项目目录由用户授权选择，不以应用沙箱隔离所有本地进程。
