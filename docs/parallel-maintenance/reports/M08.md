## 发现与修复
### BUG-M08-01（P1，已修）：临时目录含空格时，shell 语言的代码节点彻底跑不起来
`codeRunner.ts` 的 `spec()` 在 Windows 上把用户填的 shell 代码写成 `main.cmd`，再用 `cmd.exe /d /s /c <脚本绝对路径>` 跑它。`/s` 会**关掉 cmd 的「引号保留」规则**：脚本路径一含空格，cmd 会把 Node 加上的引号剥掉、在空格处把命令切断——用户填的 shell 代码一行都没跑，看到的是一句与代码无关的 cmd 报错。触发条件是**临时目录含空格**（用户名带空格的 Windows 机器、或 TEMP 被指到含空格的目录），不需要用户做任何特殊操作。

实测（修复前，真进程）：`'D:\...\maint-m08-0N3OKA\spaced' 不是内部或外部命令，也不是可运行的程序`，`status=failed`、`exitCode=1`；同一台机器上把临时根换成不带空格/带中文的路径都正常，python 与 node 两种语言在带空格路径下也正常——**只有 cmd 那一支被重新解析**。

修复（最小改动，只动这一个函数的一行 + 说明注释）：`["cmd.exe", ["/d", "/s", "/c", file]]` → `["cmd.exe", ["/d", "/c", file]]`。不带空格时本来就没有引号，行为一字不变；带空格时路径被整段保留并执行。`git diff --stat`：1 个文件 +8/−1（含注释）。

### 观察项（**未改**，登记备查）
- **OBS-M08-01（残余限制）**：临时路径里含 `&` 这类 cmd 控制字符时，引号保留规则仍然不成立（含 `/s` 与不含 `/s` 都失败，已实测并记进 observations.json）。修它需要换机制（例如由 `spawnRun` 暴露 `windowsVerbatimArguments` 或改走 shell 字符串），跨出本任务写集，交协调者定夺。
