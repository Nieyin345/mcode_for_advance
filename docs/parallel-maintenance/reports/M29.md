## 2. 修复的问题 ①:`recordFired` 用运行侧的一笔改写挂载侧事实

`automationStatus.ts` 类头的不变量:**挂载侧(`armed`/`detail`)跟着 reload 走,运行侧(`lastFire`/`lastError`)跟着运行走**。已有测试只钉了一半("reload 不抹运行史"、"blocked 不改 armed");另一半失守:`recordFired` 把 `armed` 立成 `seed.enabled`、把 `detail` 清成 undefined。

**症状**:一条文件触发器的目录监听已失效(事实正确显示「没挂上 + 目录监听失效:ENOENT」)。用户点「立刻运行一次」(手动允许照跑)之后,这一笔把事实翻成 `armed: true`、原因消失 —— 界面从此说它**响着**,用户等一个永远不会响的触发器,而"为什么"已被抹掉。参数解不开、项目不在了同理。定时/事件触发的每次自动起跑同样会把恰在此前记下的挂载失败静默洗白。

**修**(最小,±12/−2 行,仅 `automationStatus.ts`):已登记条目保持挂载侧原状 —— `armed: existing===undefined ? seed.enabled : existing.armed && seed.enabled`,`detail: existing===undefined ? undefined : existing.detail`。用户那一票仍只能把 armed **压成** false(关掉的不因手动跑一次而"响着"),不能把坏着的抬成 true;ad-hoc 守望"起跑即登记"语义不变;挂载翻回 true 仍只有 `recordSetup`(reload / 监听重试成功)一条路。
