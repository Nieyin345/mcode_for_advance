## 发现与修复

- **BUG-M20-01（P1，模型路径/状态）**：下载开始时固定旧目录，传输中设置面板可切到另一模型根；字节留在旧根，完成后新根的下载/选择状态与磁盘不符。`main/voice/models.ts` 在有 active download 时拒绝切换（包括重置），提示先完成或取消；原根和设置值保持不动。
- **BUG-M20-02（P2，取消延迟）**：取消只 abort 模型正文 GET，HEAD 大小探测使用独立 controller，可挂到单次 8 秒超时才进入取消收尾。`models.ts` 将用户取消信号接到每个 HEAD controller，并在 finally 移除监听。
- **BUG-M20-03（P2，浮层状态）**：全局 boolean 被另一闲置/卸载 pane 写成 false，或 overlay 晚于开始录音挂载时错过 true。`voiceController.ts` 按 `MicButton` 实例 symbol 记录活动所有者并向新订阅者同步当前聚合值；`MicButton.tsx` 接入实例令牌。
- **BUG-M20-04（P1，跨会话转写）**：同一 ChatPane 切 session 时内层 mic hook 可保留旧捕获；旧 stop 的 RPC 迟到仍调 `onFinalRef`，可能把旧转写写入新 composer。`MicButton.tsx` 给内层组件加 sessionId key；`useVoiceInput.ts` 只在 stop 所属 generation 仍有效时交付最终文本，取消/卸载后结果被丢弃。
- **BUG-M20-05（P1，用户文字）**：`applyLiveText` 见到新 partial 以旧 partial 为前缀，就无条件把 delta 追加到编辑器末尾；即使用户已经删改了那段尾巴，仍会污染草稿。增补 `cur.endsWith(prev)`，只在未动过的尾部继续追加；用户编辑优先。
- **BUG-M20-06（P1，重复拒绝）**：第二次同样的麦克风权限拒绝被 toast 去重条件直接 return，漏掉 `arm(false)`/错误清理，出现“监听中”假状态。去重时仍结束本次尝试，toast 仍只显示一次。

生产文件只改 `apps/desktop/src/main/voice/models.ts`、`src/renderer/components/chat/MicButton.tsx`、`src/renderer/hooks/useVoiceInput.ts`、`src/renderer/lib/voiceController.ts`。其他 M20 专属生产文件只读走查，未为了产生 diff 而改动；没有新增依赖或做未量化的性能优化。
