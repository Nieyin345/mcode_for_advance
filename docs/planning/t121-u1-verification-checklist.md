# UI 这批改动的真机验证清单

> **性质：只读盘点。** 不碰代码、不起 Electron。目的是回答一个问题：
> **今天这批 UI 改动，哪些已经有断言覆盖、哪些只有人眼能判、哪些连截图都证明不了。**
>
> 用于决定「要不要做一次真机验证、最少看哪几样」。

---

## 零、一句话结论（可直接转给用户）

> **这批 UI 改动有 42 条断言，但它们全部只验「数值关系和公式」，没有一条验过「人看着对不对」。**
> 最少要看四样：**亮色和暗色各看一次用户气泡**（它是刻意做淡的，1.08:1 会不会淡到看不见只有人眼能判）、
> **把窗口从窄拖到宽看聊天区两边留白有没有跳动**（那个倒挂是动态的，静态截图证明不了）、
> **鼠标悬停在一行会话/文件上时边框还在不在**（1.23:1 是刻意贴着下限的）、
> **本轮文件卡片里的「不可撤销」徽标在长路径下会不会把文件名挤掉**。

## 二、如果只看三样，看哪三样

**排序依据：错了代价最大 ÷ 看一眼成本最低。**

### 1. 用户气泡（亮 + 暗，各一次）

**为什么第一**：用户天天在看；**1.08:1 和 1.16:1 是刻意贴着下限做的**，而断言的下限（1.05 / 1.10）**只比"完全不可见"高一档**。这是唯一一个"断言通过但用户可能觉得坏了"的项目。

**看什么**：发一条消息，能不能**一眼认出**哪个气泡是自己的。**亮暗各一次。**

### 2. hover 态下的边框

**为什么第二**：`--edge` 从 1.75:1 降到 1.38:1（淡了 26%），而**对 hover 填充只有 1.23:1** —— 断言的下限是 1.20，**只高 0.03**。旧版本在暗色下 `--edge` 和 `--surface-hover` 是**同一个值（1.00:1）**，边框完全消失；这一版把它拉到 1.33:1，但仍然是全表最薄的一处。

**看什么**：鼠标**悬停**在一行会话/文件上，看那行的边框**还在不在**。⚠️ **静态截图看不到 hover 态，必须鼠标真的移上去。**

### 3. gutter 拖拽连续性

**为什么第三**：这个 bug 是**动态**的 —— 旧值下拖宽 1px，正文突然窄 95px。断言在数学上证明了新公式不倒挂（斜率恒正），但**渲染层**的容器查询更新、亚像素舍入只在真机上出现。

**看什么**：把窗口从最窄**慢慢拖到最宽**，盯聊天区左右留白有没有跳动。⚠️ **必须拖，不能截图。**

## 三、⚠️ 截图看不出来的（这条最重要）

**如果只做截图验证，下面这些会全部漏掉，而"截图看着还行"会被误当成"验过了"。**

| # | 项 | 为什么截图证明不了 |
|---|---|---|
| 1 | **gutter 倒挂** | 静态图是**一个瞬间**。倒挂只在**尺寸变化过程**中出现 —— 必须拖窗口或录屏 |
| 2 | **hover 态边框**（`--edge` 对 `--surface-hover` 1.23:1） | 静态截图没有 hover。必须在真实悬停时看 |
| 3 | **暗色气泡**（1.16:1） | 亮色截图完全覆盖不到。**两种主题都要，否则只验了一半** |
| 4 | **`TurnFilesCard` 徽标在长路径 / 小屏下** | 默认截图里路径通常是短的。**必须构造长路径**才会暴露挤压 |
| 5 | **sketch 主题**（`--user-bubble: 130 120 100` 配 `alpha 0.14`） | **这一项有独立机制**：sketch 主题的 alpha 是"纸张质感"的一部分，明确**不参与** CDS 对齐（注释在 `styles.css:2546`）。实测它合成出 `#ebe8df`、对纸面 **1.173:1** —— **比 CDS 亮色的 1.08:1 更清楚**，所以这次改动没有把它改坏。但默认截图只覆盖 CDS 主题，**sketch 用户看到的完全是另一套**，不截图就不知道 |
| 6 | **窗口缩放动画期间的中间态** | 截图是静止的，动画中间帧看不到 |
| 7 | **点击/拖拽/键盘焦点**（`focus-visible` 轮廓） | 静态图没有交互态 |

## 四、★ 盘点中发现的一个真问题（不在上面任何一项的断言里）

**`AppearancePanel` 的默认色块在 sketch 主题下是错的。**

- `userMessageColor` 默认是 `null`（"跟主题走"），而面板在 `null` 时显示 `DEFAULT_USER_BUBBLE_HEX = #f0f4f8`；
- 但 `html.sketch` 主题把 `--user-bubble` 覆盖成 `130 120 100`（暖灰），`alpha: 0.14`；
- **所以 sketch 用户打开设置页，会看到一个灰色色块被标成"默认"，而实际气泡是暖灰叠加。**

**这正是 `10dbb0ce` 想修的那个问题**（提交信息原文：「settings panel was contradicting all of this ... users were shown a grey swatch labelled as their current bubble and then got orange」）—— **修了经典主题，没修 sketch 分支。**

**断言为什么没抓到**：`t121-border-contrast` 那两条断言比的是 `DEFAULT_USER_BUBBLE_HEX` 与 `styles.css` 的 `:root` 值。`html.sketch` 是**另一个选择器块**，不在比较范围里。**断言是对的，但它的范围不包含 sketch。**

**这条不需要真机验证就能确认**（读代码即可），但**只有人打开 sketch 主题的设置页才会发现它影响用户**。

## 五、验完之后能说什么、不能说什么

| 做到了 | 可以说 | 不能说 |
|---|---|---|
| 只跑了断言 | 「数值和公式是对的」 | 「UI 改好了」 |
| 亮色截图 | 「亮色下看着没问题」 | 「暗色也没问题」 |
| 静态截图（任意张） | 「这几个静止状态下没问题」 | 「拖拽/悬停/动画没问题」 |
| 亮 + 暗 + 拖拽 + 悬停都看了 | 「这批 UI 改动验过了」 | 「所有主题都验过了」（sketch 仍未验） |
