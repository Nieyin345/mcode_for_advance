## 一、这个项目是什么

Mcode 是一个**本地优先的通用 Agent 桌面客户端**（Electron + React + TypeScript）。

它不自己实现 Agent 能力，而是把成熟的 Agent 引擎接进来，在上面提供一层可以自定义的
**工作模式 / 自动化 / 资产管理**：

```
用户把想要的工作方式画成一张图（工作流）
   ↓
   ├─ 手动跑：在对话里选一个模式，正常发消息，按图执行
   └─ 自动跑：触发器（定时 / 文件变化 / 事件）到点自动起一条
   ↓
节点跑在哪里分两种：子 agent 节点在自己的隐藏子会话里跑；
主代理与对话节点直接跑在主对话里（用户看得见它说话）
   ↓
产出回到对话里（结果卡片）+ 落进资料库（文献、文件、笔记）
   ↓
用量与花费可见，进程死了还能接着跑
```

**产品语义上有一处关键区分**（用户 2026-09-18 明确）：

| | 工作流（模式） | 自动化（触发器） |
|---|---|---|
| 是什么 | 像"文献精读"一样的一种**工作方式** | 像 cron / 文件监听一样**后台自动跑** |
| 入口 | 对话输入框左下角的药丸 | 设置 → 自动化 |
| 怎么跑 | 选中模式 → 正常发消息 | 条件满足自动跑；也可手动「立刻运行一次」 |
| 要"运行按钮"吗 | **不要**（选中即用，像选模型） | 要 |

这条区分推翻过一个看似合理的改进（"普通工作流缺一个运行入口"）—— 加它反而会污染语义。

**八个内置节点类型**（都在 `nodeTypes.ts` 的 `BUILTIN_NODE_TYPES` 里）：

- `mcode.main` —— 主代理。用户那句话进图的第一站，一份工作流**有且只有一个**、删不掉；
  **跑在主对话里**（执行方式是 conversation，用户看得见它拆解与分派）；
- `mcode.agent` —— 子 agent。跑在自己的隐藏会话里，是干活的主力；
- `mcode.conversation` —— 跑在**主对话**里的模型轮（不另开会话）；
- `mcode.branch` —— 岔路口。出路写在**边**上（label / note），用户可以选，也可以让模型判；
- `mcode.condition` —— 声明式条件判断，AND/OR，true/false 分流；不调用模型，也不是人工回环闸门；
- `mcode.command` —— 跑一条命令。**非零退出码不算这一步失败**（失败的是命令，不是流程）；
- `mcode.code` —— 跑一段代码（Python / Node / Shell / PowerShell）；
- `mcode.trigger` —— 触发器。自动化的入口，自己不跑东西。

插件可以注册自己的类型（`nodeTypes` 是第一个由 Mcode 自己消费的插件组件种类）。

**执行分派只有一个入口**：`manifest.runner.kind` 在注册表里就交给它，没有就落兜底
（模型轮）。新增一种执行方式 = 注册一个执行器，分派链一行不改。

**三条硬约束**（校验层拦，不只靠界面）：
- 普通图型工作流必须有且只有一个 `mcode.main`（自动化以触发器为入口）；
- 自动化至少有一个触发器（从前 0 个触发器会静默降级成普通工作流）；
- 每个节点都可以有产出变量（`code` / `command` 也补齐了）。

### 3. 自动化

三种触发器都**接了调度器、真的在跑**：定时（cron）、文件变化（watcher + debounce）、
事件（挂在 hook 事件表上）。有防重入（同一自动化运行中跳过）、有仪表盘（**按条触发器**
的挂载事实 / 运行状态 / 最近一次 / 报错；per-trigger 启停开关**尚未实现**，仪表盘不显示
假的"已启用"）。触发器载荷以 `{{trigger.*}}` 进入变量系统。

### 5. 记忆 / 监控 / 守望

- **记忆**：文件式长期记忆（存储 / 检索注入 / 维护三件套）。
- **监控**：运行概览与历史。
- **守望**：绑定会话运行命令，退出后将结果交回会话；不同于已退役的「长任务」自动续轮。

「长任务」按钮、状态条、循环器与 RPC 已移除；历史数据库中的任务行不会在升级时销毁或改写。

  输入框里的会话级插件名单已退役，历史列保留但不再读写。

- **模板库**、**IDE**（文件树 / 编辑器 / Git / 终端 / LSP）、**内嵌浏览器**、
  **手机端**（局域网 + 中继两路）、**语音输入**、**用量统计**。

## 四、怎么在这个项目上干活

### 验证

```bash
bash apps/desktop/scripts/run-all-smokes.sh
```

```bash
npx tsc --noEmit -p apps/desktop/tsconfig.json && npx tsc --noEmit -p packages/contracts/tsconfig.json
```

两样都必须干净才算做完一件事。**40 套 smoke 的正确数字是基线**，不是"大概过了"。

### 几条硬规矩

1. **先补测试，再动刀。** 大重构之前先给要改的路径写断言 —— 没有护栏的重构是在高空作业
   （`ingestEvent` 拆分前先把覆盖从 70 条补到 104 条，就是这一步救了场）。
2. **共享实现只有一份。** 「用户点的」和「AI 调的」必须走同一个函数，否则迟早分叉
   （资料库的挂载、自动化起跑都遵守这条）。
3. **坏东西要显式报出来，不静默跳过。** 挂不上的关联要数出来、屏蔽挡下的要写进清单开头、
   读不回来的存档要当"卡片过期"说清楚。
4. **重构用 AST 定边界，不手抄代码。** 这个仓库注释密度很高，手抄必然改坏。
5. **临时脚本先写文件再执行**，不要写内联的一行命令（PowerShell 多层转义 + 中文路径必炸）。
6. **git 取消暂存用 `git restore --staged`，永远不要 `git checkout HEAD -- <文件>`**
   （后者会连工作区一起覆盖）。

### 需要留意的环境事实

- 数据库是 **sql.js**（纯 WASM SQLite）—— **没有 FTS5**，全文检索走 ripgrep。
- **`db.export()` 会重置连接上的 pragma**（包括外键）。导出只有 `exportBytes()` 一个出口，
  新增导出点要走它。
- 主进程里**没有 cookie 的 HTTP 请求做不到**（要走内嵌浏览器那条路）。
- **API 并发上限是 2** —— 不要并行派多个 subagent（会静默返回空），需要多路调研时串行读
  反而更稳。
- 手机端（`AppMobile.tsx` + `webApi.ts`）是一棵**独立的组件树**，走的是没有 preload 的
  HTTP 桥。**共用组件里每加一个 RPC 都要在 `webApi.ts` 补一项**，漏了会同步抛错，
  React 19 会因此整棵卸载。
- `.tmp/` 下有现成的**组件预览台**（`ask-preview` / `retry-preview` / `card-preview`），
  用来在真浏览器里核对渲染端；`.claude/launch.json` 放在**会话所在文件夹**而不是 cwd。
