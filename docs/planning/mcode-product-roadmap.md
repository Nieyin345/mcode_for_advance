## 1. 产品定义与目标用户

Mcode 是服务**技术型个人用户与小团队**的本地优先、可高度自定义的**通用 Agent 平台**。

目标不是分别内建编程、科研、写作、绘图、法律、金融等封闭场景应用，而是让用户或 AI 通过 Skills、工具、工作流、自动化、专业 Agent 与扩展组合出场景能力。AI 可以根据用户的自然语言描述**创建、测试、修复并安装扩展**，用户也能自行开发和管理扩展。特殊业务不应硬编码进宿主。

首个贯穿验收用例可选用科研数据分析与报告生成，但它只是底层能力是否贯通的测试，不得转化成宿主内置的科研专用提示词、硬编码工具或固定流程。

## 2. 近期四条并行主线与交付节奏

| 主线 | 近期交付目标 | 设计边界 |
|---|---|---|
| **UI 与统一工作台** | 统一会话、项目、文件、Git/Diff、终端、任务、审批、Office、工作流的可见状态和操作 | 保持数据/工具/工作流的单一业务入口，真实 Electron U1 为关键验收 |
| **GenOffice** | 整合原厂 Docs、Sheets、Slides、PDF、Markdown、HTML 六类编辑器的完整可用能力及真实文件交付 | 以原生源码、编辑器与引擎为基础，Mcode 写受控 Host/IPC 薄适配；CLI 成功不是 GUI 完成 |
| **Node-RED 工作流/自动化** | 原生画布、运行时、存储、触发权与 Mcode Agent/Host/权限统一 | 唯一流程内核、唯一触发/存储事实源；不长期保留两套运行器或双触发 |
| **共享底层能力** | 原生三 SDK/Provider、统一工具目录、Git、终端、文件、资料库、记忆、权限、会话/任务、执行可靠性 | 不重造 Agent loop，已有能力优先复用；随上游 SDK 演进，在兼容验证后升级 |

**同步推进，而不是串行等整条产品线完成。** 按独占文件/接口与测试环境的边界拆分任务；跨线阻塞性缺陷优先消除，不为提升表面进度而跳过安全和验收。

**长期项目：扩展生态。** 优先复用 Mcode ModuleHost、Skills、MCP、Node-RED 节点与许可允许的成熟兼容运行时，目标是尽可能让已有 VS Code 插件（含 VSIX）少改或无需修改即可运行。逐步验证真实兼容范围，再评估扩展市场接入；Chrome/Obsidian 等其他生态暂不进入近期范围。扩展生成、安装、版本、回滚、沙箱、撤权和审核必须走 Mcode 的统一宿主规则。

## 3. Agent、任务与执行系统

- **通用 Agent 默认入口。** 编程/写作/研究等专业 Agent 是保存、复用和组合的角色配置；Agent 引用 Skills、工具和工作流而非复制一套执行器。低风险任务可自动路由已有专业 Agent，复杂任务由协调 Agent 按依赖图（DAG）分工并行；用户可检查和调整。
- **任务是一级对象，不依附聊天。** 一个任务有稳定 ID、目标、依赖、审批、状态、日志、检查点、产物、验收证据，可以由聊天、工作流、自动化和多个 Agent 关联或推进。
- **验收与执行状态区分。** 执行完成不等于验收通过；失败应返修、重新验证，遇到无法自动决策、权限或不安全条件才明确请求用户介入。证据不够应标 BLOCKED/FAIL，而不是报告成功。
- **自主执行按授权策略配置。** 辅助模式、监督执行和受控自动化可按 Agent/项目/任务选择；新创建或第三方 Agent 默认监督执行；扩展不得自行提权，高风险或越权动作由用户审批。权限、文件版本 CAS、幂等与审计由 Host 统一落实。
- **模型/Provider 路线。** 支持 API、官方支持的登录/认证方式（如适用的 Claude/Codex），未来可研究网页模型参与控制 Mcode 的浏览器桥。现有三家 SDK 保留原生能力；升级通过兼容矩阵与测试验证，禁止静默更换未授权的 Provider。
- **执行环境由用户选，AI 不调度。** 项目可以记住默认环境，单任务可以覆盖；逐步支持本机、Docker、远程服务器、云环境、WSL、虚拟机等。统一环境管理器提供连接与依赖检查、执行状态和结果；环境不可用就明确报错，不自动切换。远端文件同步与挂载按项目授权规则处理，传输范围明确，凭据不得落进普通日志/记忆。

## 4. 记忆与通用知识

- **分层上下文：** 全局偏好、项目/专业上下文、当前任务上下文独立管理，可受控共享。
- **长期记忆事实源：** 继续使用用户可编辑的 Markdown；索引、向量与缓存属于可重建派生数据。
- **记忆生成与注入：** AI 主动发现候选，但持久写入遵守用户授权；稳定背景少量自动注入，任务相关记忆动态检索，必要时按需深入，保留来源及作用域。
- **专业能力沉淀：** 经核实的任务方法可抽象成 Skill/专业 Agent 配置；任务中间产物与日志不必全部长期记忆化。

## 5. 首阶段验收与交付门槛

1. **单线交付：** UI、GenOffice、Node-RED/自动化等分别按自己的 E1/E2/U1 规则验收，先交可用切片。
2. **核心产品闭环：** 用户从 UI 提出通用任务；Agent 在已授权范围内调用文件/Git/终端/Office/工作流，生成可用的真实产物；任务中心能追踪状态、失败、审批、产物与证据。用户能完成、返修并重新验收。
3. **持续平台演进：** 多 Agent 深度并行、跨环境执行、全面暂停/恢复、AI 扩展工厂、VS Code 扩展生态逐步形成，不强制在第一阶段全部交齐。

**验收纪律：** E1/headless 只能证明覆盖路径，不等于真实 Electron U1；论文/科研验证场景不构成宿主特化理由。已有台账 ARC-005/006/007 和 MC/UXG 的状态不能因本路线被批准而自动改成完成。
