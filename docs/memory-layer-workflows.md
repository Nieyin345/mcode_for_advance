# 分层记忆与手动工作流

> 本页记录上一阶段。后续已升级为主页面一键后台自动化与独立临时交接，当前入口和生命周期见 [记忆助手与临时交接](memory-assistant-handoff.md)。上一阶段的模板注册遗漏已在该轮补齐。

## 设计结论

沿用既有引擎，不再建立一套“记忆工作流引擎”，也不把四种上下文复制成四个长期库。

| 层 | 职责 | 生命周期 / 边界 |
|---|---|---|
| 系统 / 全局记忆 | 用户明确认可的跨项目偏好、经验和事实 | 既有 global Markdown 范围；不是权限规则的替代品 |
| 项目记忆 | 当前项目的长期事实、决策、经验 | 既有项目隔离、检索、版本校验与修改历史 |
| 工作流上下文 | 运行记录、节点输入输出、任务检查点 | 复用 runStore 和已有产物；不能自动视为已验证长期事实 |
| 子代理上下文 | 角色、节点/子对话历史、可选创建快照 | 原有持久节点会话继续复用；不另建一份共享长期库 |

分层不等于指令权限等级。记忆不得覆盖宿主安全限制或用户当前明确指令。项目明确例外可以覆盖全局默认偏好，但相互矛盾的事实仍需回查证据或询问用户。

## 本次修复

1. **工作流拥有本步注入决定权。** 普通聊天继续自动读取其项目＋全局快照。工作流主节点、对话节点及隔离节点由原有节点开关决定注入，RuntimeManager 不再额外叠加普通聊天快照。内部标记也随模型回退重试保留，不暴露为模型或 IPC 可控权限。
2. **启动快照有独立队列槽。** 复用尚未开始的子对话时，更新、关闭或清空记忆只替换 / 撤销 `memory.creation-snapshot`，不丢失独立的工作流回流产物。真正投递时分别标明“工作流结果”和“创建时记忆快照”。
3. **修改来源由宿主生成。** `memory_write` 经可信会话查得 sessionId、kind 和可用的 parentSessionId/nodeId，保存到 Markdown 的 `mcodeLastWriter` 元数据。模型不能通过工具参数伪造这些值；人工编辑保留已有来源标记。该字段表示最近工具写入的来源线索，不是防篡改审计、事实验证，也不表示后续人工编辑仍由该代理完成。不用会话配置里的 workflowId 冒充本次实际运行 ID。
4. **审批说明更清楚。** 说明项目 / 全局范围、宿主执行上下文，以及临时结果不应直接升级为长期事实。原有显式审批、修订校验和历史归档继续有效。
5. **界面说明与入口。** 记忆面板新增四层职责说明；通过现有工作流选择器 / 工作流库提供以下三项，沿用现有非模式工作流名称映射与中英文文案。

## 三个手动模板

### 整理本次成果 — `memory-capture`

当前对话提取候选 → 子节点检索 / 读取原记忆并核实 → 最后一个节点请求宿主逐条审批写入。

- 默认只写当前项目；用户明确指定跨项目共享时才选全局。
- 区分已证实事实、明确决策、失败经验、偏好、临时进度与猜测。
- 更新携带真实路径和 revision；冲突后重读、重核对、重新确认，不强制覆盖。
- 新增使用稳定主题路径和 create-only 语义；已存在且内容相同应跳过，不用时间戳 / 随机名制造副本。
- 拒绝后不换工具绕过。没有成功工具结果不能报告“已保存”。
- 候选 / 建议是普通工作流产物，不是新建的候选数据库或专属收件箱。语义查重仍依赖检索与核对；没有宣称事务级 exactly-once 或跨路径语义去重保证。

### 保存任务检查点 — `memory-checkpoint`

把目标、验收条件、用户限制、证据、完成 / 进行中 / 阻塞状态、修改文件、验证结果、未知事项和下一步输出为运行结果，复用既有 runStore 留存。

不自动写长期记忆，不自动新建对话，不恢复原执行进程。用户可从运行记录取回检查点，放入新会话继续。

### 检查记忆健康 — `memory-health`

列出并按需读取当前项目和显式全局的记录，报告疑似重复、冲突、适用条件变化、证据不足及建议保留项，注明实际检查范围。不能仅凭时间较旧判过期，不能把同名不同条件当重复。

只提出维护建议，由用户在已有记忆整理 / 历史界面复核。本模板的只读目标是模板指令约束，不是独立的工具白名单沙箱；任何受控记忆修改仍需要既有宿主审批。`capability: read` 本身不等于禁止所有工具写入，主对话节点仍使用主对话权限。

## 如何使用

- 完成一阶段工作：手动选择“整理本次成果”，检查候选和审批内容。
- 准备切换会话 / 暂停任务：选择“保存任务检查点”，之后从该次运行记录取回。
- 怀疑记忆重复或冲突：选择“检查记忆健康”，先看报告，再决定是否维护。
- 三个模板均无触发器，不新增事件监听、定时任务或写入后自触发链。原有自动化循环保护不变。

## 边界与未包含内容

- 关闭注入不会删除已经发送给提供方的历史，也不禁止模型按需调用可见范围内的记忆检索工具；需要新上下文时开新会话。
- 待投递的创建快照仍为内存队列，进程重启不保留；既有会话历史和运行记录按原机制保存。
- 通用文件 / Shell 工具并未由本模块沙箱化。禁止绕过的指令不替代文件系统权限控制。
- 此处子代理主要指 MCode 管理的节点 / 子对话；来源元数据标记宿主会话，不宣称追踪所有原生 SDK 内部子代理身份。
- 没有自动遗忘、自动事实裁决、自动删除、记忆效果评测仪表盘或独立候选收件箱。
- 无真实模型调用、GUI 点击或三家原生运行时端到端验收。隔离测试不等于这些验收。
