# Mcode 功能文档（最终目标）

> **这份文档写的是 Mcode 最终要做到什么**，不写现状、不写实现细节。
> 用来让其他模型（或人）逐条对照代码检查：哪些已经做到、哪些没做到、哪些做了但行为不对。
>
> **给检查者的说明**
> - 每条功能有编号（如 `CHAT-03`），报告问题时请引用编号，并给出代码位置与复现方式。
> - 「应当」后面写的是验收标准，按这个判定，不要按自己对同类软件的想象判定。
> - 文档里写明「不属于本条」「由 X 负责」的边界，是产品决定，不要当缺陷报。
> - 只检查 **Windows** 上的行为；macOS 安装包照常打，但不是检查重点。
> - 不需要、也不要启动真实模型或联网去验证；读代码、跑仓库里已有的测试即可。

## 一、产品定位与总原则

Mcode 是一个**本地优先的通用 AI 代理桌面工作台**，主要面向**科研（文献、论文写作）和写代码**。
它不自己实现代理能力，而是把成熟的代理引擎接进来，在上面提供：对话、资料库、编辑器/IDE、
工作流与自动化、记忆、手机远程、对外 MCP 等一整套工作环境。

总原则（适用于全部功能）：

| 编号 | 原则 |
|---|---|
| P-01 | **本地优先**：会话、资料库、模版、工作流、记忆都存在本机同一个数据目录里，可以整体迁移。 |
| P-02 | **界面中文为主，同时提供英文**；所有界面文字走 i18n，不硬编码。 |
| P-03 | **出错要让用户看得见**：保存失败、发送失败、创建失败等，必须有提示（toast / 内联错误），不能只进控制台或静默吞掉。 |
| P-04 | **不丢数据**：编辑器、设置、消息落库在并发、切换、重启时都不应丢改动；外部改动与本地改动冲突时要提示而不是覆盖。 |
| P-05 | **密钥不外泄**：API Key、令牌不返回给模型、不出现在日志和远程接口的返回里，界面上一律打码显示。 |
| P-06 | **危险操作每次都要用户批准**（删除/移动文件、执行任意命令、终止进程等），对外暴露的接口里不允许「总是允许」。 |
| P-07 | **提示文字能藏就藏**：界面保持简洁，说明性文字放在可展开的提示里，符合常规软件的使用习惯。 |
| P-08 | 升级不破坏已有数据：老数据（旧会话、旧工作流、旧设置）升级后照常可读可用。 |
| P-09 | **外观以 Claude 桌面端为基准**：主界面的区域划分、尺寸、间距、字号、圆角、动效一律照 Claude 桌面端的 Code 工作区，不自行发明。Mcode 独有的功能走 Claude 已有的入口，不在骨架上新增区域或按钮。详见第十四节。 |

## 一之二、UI 外观基准（Claude-first，2026-10-27 定）

> **这一节是硬约束，不是建议。** 之前几轮"改成 Claude 风格"没有效果的根因是：
> 只在旧布局上叠加 CSS 覆写（`styles.css` 里 154 条 `[data-ui-shell-variant="workspace"]` 规则），
> 而 DOM 结构、区域划分、尺寸体系全是 Mcode 自己的。**外观不等于配色。**

### UI-01 基准来源

- 外观唯一基准是**用户本机安装的 Claude Desktop**，不是第三方逆向文档。
- 当前基准版本：**3.1623.4.0**（Electron 44.9.0，MSIX，`C:\Program Files\WindowsApps\Claude_3.1623.4.0_x64__pzs8sxrjxfjjc`）。
- 数值来源是**可重跑的抽取脚本**（`.scratch/claude-ui-extract/extract.py`），从该安装包的
  `ion-dist/assets/v1/c6a992d55-Bt_TAkxU.css` 读取。当前已抽出 **1027 个 `--cds-*` token**，
  其中 **121 个随 `data-density` 切换**（compact 182 条规则 / comfortable 95 条）。
- Claude 升级后**重新跑脚本**，不手工改 token。
- **不取**：JS 代码、图标字体文件、Anthropic 专有字体文件。只取 CSS 数值与规则。

**已被证伪的旧依据**：`docs/design/claude-code-reference-matrix.md` 与
`docs/design/claude-desktop-ui-细节逆向.md` 基于 2.x 版本；其中
`--static-sidebar-width`、`--chat-leading` 等名字在 3.1623.4.0 的产物里**不存在**。
这两份文档可以继续当历史参考，但**不能当外观数值的来源**。

### UI-02 只做 Code 页，不做 Cowork

- 照抄范围是 Claude 的 **Code 工作区**形态，**不包含 Cowork**（多代理协同画布）。
- Cowork 相关的界面元素一律不出现。

### UI-03 结构照抄，不是配色照抄

以下结构必须与 Claude 一致，不能保留 Mcode 现有形态：

| 结构 | Claude 的做法 | Mcode 现在的做法（要改掉的） |
|---|---|---|
| 主列切换 | `data-chat-column="project" \| "thread"` **列覆盖**：打开会话时 thread 列盖住 project 列 | 左栏/中栏/右栏**同时并存**、各自独立 |
| 右侧内容 | **pane tile 模型**：`paneTileId` / `paneTileKind` / 可拖分、可弹出成独立窗口 | 固定一栏 + 八个固定页签 |
| 密度 | `<html>` 上 `data-density` 属性**一条规则翻转整套尺寸**（compact/comfortable） | 各组件自己写死 Tailwind 尺寸类 |
| 尺寸 | 全部读 `--cds-*` token，且**字号与行高成对定义**（如 14px 字号 ↔ 20px 行高） | 行高按密度档写死 `1.5/1.6/1.75` |

### UI-04 Mcode 独有功能的挂载方式

Mcode 比 Claude Code 多出的功能（Office 六编辑器、资料库、工作流、自动化、记忆、插件、手机远程）
**不新开界面区域**，按下面三档挂载：

| 档 | 功能 | 挂在哪 |
|---|---|---|
| 左栏入口 | 资料库 | 左栏底部入口（与 Claude 的 Settings 入口同级），点开在主列显示；内容复用 Claude 的「项目」树的外观（同样的行高、图标位、展开箭头） |
| 右侧 pane | 文件树、Git、终端、浏览器、文档视图 | 填进 Claude 已有的 pane 位置，用相同的 `paneTileKind` 机制 |
| 已有入口 | 工作流、自动化、记忆、插件、设置 | 走命令面板（Ctrl+K）与设置页，**不在主界面加新按钮** |

### UI-05 验收判据

- **判据不是"看着像"**，是**与 Claude 同尺寸、同主题、同 DPI 的截图逐屏对照**。
- 对照集至少覆盖：空会话、有消息、工具运行中、工具失败、审批等待、diff 查看、
  终端、文件树、设置页、窄窗（1024×640）。
- 每屏同时记录浅色/深色。
- **禁止用 PNG 哈希证明"零变化"**（两轮连跑只有 12/48 张相同，见
  `apps/desktop/scripts/arc005-visual-baseline/README.md` §3）。截图用于**人对人比对**，
  机器判据用 `getComputedStyle` 的具体字段。
- 只要对照集里还有一屏没对上，UI 重构就不算完成。

### UI-06 旧界面不长期保留

- 新外观落地后**删除旧的 `classic` 外壳变体**，不长期维护两套界面。
- 迁移过程中可以短暂共存，但必须有明确的删除时点，不允许"两套都在、谁都不改好"。

## 二、AI 对话

### 引擎与模型

**CHAT-01 三个本地引擎**
- 应当支持 Claude（Claude Agent SDK）、Codex、Pi 三种引擎，开新会话前可选。
- 三个引擎在以下方面行为一致：流式输出、工具调用与审批、提问（AskUserQuestion）、
  token 用量、中断、结构化输出、轮预算、失败回退。
- **两项按引擎能力差异处理，不强行对齐**：
  - **子代理**：Claude 与 Codex 有，**Pi 没有**（它的 SDK 不提供后台子代理工具）。
    界面在 Pi 下不显示子代理面板，而不是显示一个空的。
  - **花费（美元）**：Claude 与 Pi 上报，**Codex 不上报**（它的 token 快照里没有金额）。
    Codex 下只显示 token 用量，不显示一个猜出来的金额。

  这两项的共同点：**做不到就不显示**，而不是显示一个看起来有值的假数字。

**CHAT-02 自定义模型（OpenAI 兼容接口）**
- 应当能在设置里添加 OpenAI 兼容接口（地址 + Key + 模型名），给引擎使用。
- Key 默认只显示打码串。**用户可以主动点「眼睛」看一次明文** ——
  那是刻意的取用口（用户要核对自己填的 key 是不是对的），不是泄露：
  明文只在用户点击时经一次 IPC 取回、只显示在那一个输入框里，不写入任何日志或状态。

**CHAT-03 网页模型（另一种 API 来源，不是引擎）**
- 应当能通过浏览器扩展桥，把网页版大模型当作一个 API 来源使用。
- 它是「另一种 API」，挂在引擎下面用，**不是第四个引擎**。
- 至少支持 DeepSeek 网页版和 ChatGPT 网页版两个站点。

**CHAT-04 引擎安装与健康检查**
- 设置 →「引擎/运行时」能看到各引擎是否可用、版本，必要时一键安装或给出明确的修复提示。

### 对话流程

**CHAT-05 流式对话**
- 回复实时流式显示（文本、思考过程、工具调用、工具结果）。
- 长对话（数百条消息）流式输出时界面不卡顿。

**CHAT-06 工具审批**
- 工具调用需要批准时显示审批卡：允许 / 总是允许 / 拒绝；桌面和手机任一端回答都生效，另一端同步消失。
- 回答后卡片消失、输入框恢复，不会出现输入框被锁死的情况。

**CHAT-07 计划模式**
- 能先让模型出方案，用户批准（可编辑方案、可附反馈）后再动手。

**CHAT-08 提问**
- 模型向用户提问时显示问题卡，可选择/填写答案或关闭；回答后同一轮继续。

**CHAT-09 中断与排队**
- 运行中可以停止当前回合。
- 运行中发的消息进入队列，回合结束后依次发出；队列可查看、可清空。
- 运行中按 Ctrl+Enter 可「插话」：插入到当前回合；失败时有提示。

**CHAT-10 输入框**
- 支持：文件标签、粘贴图片、粘贴文件、**从资源管理器拖文件进来**、斜杠命令、语音输入、长文本粘贴自动转成附件。
- 图片作为图片内容发给模型；其它文件以路径标签交给代理自己读。
- 输入框左下角能切换工作模式（见 MODE），能选引擎/模型、工作目录、git worktree 模式。

**CHAT-11 斜杠命令**
- 内置命令 + 各引擎自带命令 + 技能命令都能在 `/` 菜单里找到，按当前引擎过滤，显示说明。
- 项目初始化方案以 `/init-名称` 出现（见 MEM-06）。

**CHAT-12 消息操作**
- 复制、编辑后重发、重新生成、选段引用（带行号）、书签。
- 用户能对任一条 AI 回复「重新生成」。

**CHAT-13 每轮改动与回退**
- 每一轮改了哪些文件都有记录；可以一键回退到这一轮之前（只回滚文件）。
- 在对比视图里可以**逐块撤回** AI 的某一处修改。

**CHAT-14 轮预算与失败回退**
- 设置里可开「每轮预算」：最多轮数 / 最多花费（美元）/ 最多 token。任一达到就在**回合中途**停止并提示原因（三个引擎都要能中途停，不是等回合结束）。
- 可配置失败回退模型链：模型报错时自动换下一个模型重试（只用于普通对话）。

**CHAT-15 上下文与用量显示**
- 状态栏显示上下文占用环（已用 / 上限 / 百分比、接近上限时警告），没有数据时显示空环而不是消失。
- 每轮显示耗时、token、花费。

**CHAT-16 会话管理**
- 多会话、多标签；会话可重命名、置顶、归档（含自动归档）、删除、搜索、分叉（复制一份从某处继续）。
- **分叉只在 Claude 会话里提供**：分叉要复制**宿主侧的会话状态**，只有 Claude 的 SDK 能给出
  可续的会话 id。Pi 与 Codex 下这项**不显示**（它们自己的 `/fork` 是 TUI 里的命令，
  与这里"带着上下文另起一段"不是同一件事）。
- **侧聊 / 子对话**：另开一条旁支提问，不打断主对话。
- 会话右键：复制会话 id、挂载到当前对话（让当前对话读另一个会话的记录）。
- 会话标题自动生成（可配置用哪个模型）。

**CHAT-17 子代理面板**
- 能看到当前回合起的子代理：名字、状态、过程；子代理跑完不丢上下文。

**CHAT-18 代理之间通信**
- 代理之间可以互相发消息（通知，不等回复）和提问（要等回复）。
- 发出和收到的信件在**双方对话里都直接显示全文**（发信方显示「发给 / 向…提问 / 回信给」卡片，收信方显示来信卡片），并显示送达情况。

**CHAT-19 输出风格**
- 可选择/自定义输出风格，对 Claude 会话从下一轮起生效。

**CHAT-20 视觉能力是统一的一套（不是各模块各写一份）**
- **模型能看图**：用户在对话里发图片，模型收得到并能据此回答。粘贴、拖入、附件三条路都成立。
- **用户能看图**：图片在对话里按原始比例显示，可点开查看大图；不因为尺寸大就压成一条横线。
- **AI 改完能出预览**：文档/演示被改过之后，能直接产出一张预览图给用户看效果，不必另外打开文件。
- **浏览器截图与文档预览走同一个能力**：截图、文档快照、图片查看共用同一套存储与展示，不各成一套。
- **看得见"AI 看了什么"**：AI 在读一张图（用户发的、浏览器截的、文档渲染的）时，对话里像 Claude
  那样显示那张图的缩略图，用户能核对它到底看到了什么，而不是只看到一句"我看了图片"。

**CHAT-21 图片进模型的边界**
- 模型不支持视觉时，**明确告知**「这个引擎/模型不能看图」，而不是把图丢掉后假装看过。
- 图片过大时按需降采样，并在对话里说明「已缩小」，不静默改变模型看到的内容。

## 三、工作模式（MODE）

**MODE-01 六种内置模式**
- 默认、文献检索、文献精读、文献写作、文献评审、代码编辑；在输入框左下角切换，选中即用（不需要运行按钮）。
- **六种里只有「默认」随安装就在**。其余五种是**预设**（`resources/presets/workflows.json`），
  用户在「工作流 → 导入预设」里按需装。这是 2026-10-10 的决定：release 版不内置任何可选内容，
  一切由用户自建；装着不用的模式会一直占着下拉列表和系统提示词预算。
- 每种模式的提示词都能在设置里修改，并能「恢复默认」。**「恢复默认」回到的是
  「设为默认」时钉下的那一版**，不是出厂版 —— 用户替换过的模式不该被一次误点抹掉。

**MODE-02 两层提示**
- 「文件架构与读法」（东西在哪、怎么读、有什么规矩）每轮、每种模式都注入。
- 模式自己的流程提示只在选中该模式时注入。

**MODE-03 流程脚本**
- 模式配套的**查库 / 核对**脚本随应用发布，落在数据目录；用户没改过的脚本随版本自动升级，
  改过的保持不动（靠内容哈希判断「改过没」）。
- **不内置「检索脚本」**（2026-09-22 决定）：文献检索与下载由外部 MCP 工具与模型自己完成，
  宿主硬塞一份检索脚本等于把"怎么检索"锁死在宿主里，而且各库的检索语法一直在变。
- **核对脚本只在用到它的工作流被导入时落盘**，不无条件铺进数据目录 —— 没导入那份工作流的
  用户不该在数据目录里看到一堆用不上的 `.py`。

## 四、资料库（LIB）

> 统一名称是「资料库」。资料库是通用的资料管理（论文、教材、笔记、文档、幻灯、LaTeX、代码、图片……），不是只针对文献。

**LIB-01 分类**
- 三级分类：大类 → 类型 → 集合（分类），三级都能新建、重命名、删除、移动。
- 每一级都能写「给 AI 的提示词」，逐级叠加注入。
- 用户可以自建类型。

**LIB-02 条目**
- 支持：导入任意文件（PDF、Word、PPT、图片、代码……）、文件夹条目、单条笔记。
- 作者、年份、期刊、DOI、arXiv 等学术信息的提取、规范化和标识去重由**对应自动化**负责；核心不重建独立学术字段或内置提取器。
- 自动化把引用信息保存为可关联、存储和展示的笔记 / Markdown / 产物；核心文件内容哈希去重与自动化 DOI / arXiv 去重是两件事。
- 条目可以同时属于多个分类。

**LIB-03 关联**
- 条目之间可以建关联（一对多，可关联库外文件）；双方都看得到（「我关联了谁 / 谁关联了我」）。
- 引用一条条目时，它关联的条目自动一起挂上（一跳）。
- PDF 转出的 Markdown 和它的图片目录与原条目视为一个整体（一起显示、一起删除）。

**LIB-04 屏蔽规则**
- 可按任意层级节点或按文件类型屏蔽「给 AI 看的内容」，向下继承；屏蔽 PDF 时如果有转录 Markdown 就只给转录。

**LIB-05 回收站**
- 所有回收站合并成一个，固定在最底部。
- 从分类里移除条目时：只有它不再属于任何分类才进回收站。
- 回收站里**只删除、不还原**（彻底删除时展示连带的关联，让用户勾选）。

**LIB-06 检索与浏览**
- 能按关键词检索标题、摘要、来源、文件路径；库内全文检索在命令面板（Ctrl+K）的「文档」页签里。
- 左栏树状浏览；右栏预览（PDF、Markdown、图片、Office 文档）。

**LIB-07 转 Markdown**
- 转 Markdown 由**已配置的在线转录自动化**负责（例如 MinerU 在线接口），核心只导入文件、保存/展示并采纳产物，不直接执行转录。
- 启用并配置的自动化可以自动上传文件；是否上传由该自动化配置决定，不能把“不给 AI 看”的屏蔽开关误当上传许可开关。
- 自动化没配置令牌时**跳过**并说明原因，不当作核心导入失败；不得偷偷改走本地 PDF.js 或其他本地抽取降级。

**LIB-08 文献检索与下载的分工**
- DOI / arXiv 检索与 PDF 下载由**配置的自动化调用外部 MCP 工具 / 内置浏览器**完成；
  核心负责把结果导入资料库、归入分类、校验下载的确实是 PDF，不内置直接下载/学术提取。
- **机构认证（学校登录入口 / 代理前缀）已整体退役**（2026-10-11）。它要求宿主管理用户的
  机构账号，而那既难做对（各校 SSO 千差万别）也不该由客户端持有。需要机构权限的场景，
  在**已登录该机构的内置浏览器**里手动走完登录，再让自动化用那个浏览器会话。
- **Mcode 提供 `agent_read_url`**（读一个网页取正文）—— 它是常驻的 agent 工具，
  不是"联网搜索"。检索本身交给模型或外部 MCP；宿主不内置搜索引擎。
- 「文献导入」类预设**由事件触发**（`library.item.imported`）而不是只手动：
  导入一篇就接着处理，正是这个客户端想省掉的那一步。手动运行仍然可用。

**LIB-09 模版**
- LaTeX、Word、PPT、代码、图片模版在资料库里统一管理（不是独立的「模版库」入口）。

**LIB-10 AI 使用资料库**
- 每轮给 AI 的是**清单（路径）**，AI 用文件工具自己读，不把全文塞进上下文。
- AI 有一组资料库工具（查分类、搜索、列条目、看关联、写笔记、建关联等），效果与用户在界面上操作一致。

## 五、编辑器与文档（EDIT）

> **Office 一律走 GenOffice 原生编辑器内核**，不再有第二套实现（OnlyOffice 已于
> 2026-10-24 整体移除）。Mcode 只做宿主：打开、保存、权限、冲突、AI 归它；排版、
> 表格引擎、渲染树归 GenOffice 原厂代码。**不重写编辑器内核，也不另造一套。**

**EDIT-01 文件树**
- 右栏文件树标出 AI 本轮新建/修改的文件；支持新建、重命名、移动、复制、删除、在资源管理器中打开。
- 单击预览、双击在中间栏打开。

**EDIT-02 代码编辑器**
- Monaco 编辑器，支持 30 多种语言；编辑 / 对比 / 预览三种视图。
- 磁盘上的文件被外部（包括 AI）改动时：没有本地未保存改动就自动刷新；有冲突就提示，不静默覆盖任一方。

**EDIT-03 Markdown**
- 所见即所得 / 预览 / 源码三档，默认所见即所得；没编辑不写盘。
- 长文滚动加载（看到哪里加载哪里附近）；预览里的相对路径图片正常显示；支持公式。

**EDIT-04 六种文档格式都用原厂编辑器在应用内编辑**
- 支持的格式与归属：`.docx/.odt/.ott` → 文档；`.xlsx/.xlsm/.xls/.csv/.tsv/.ods/.ots` → 表格；
  `.pptx/.odp/.otp` → 演示文稿；`.pdf` → PDF；`.md/.markdown/.txt/.json` → Markdown；`.html/.htm` → HTML。
- 打开这些文件**默认直接进原生编辑器**，不再先问「要不要用预览」。编辑器页面与预加载脚本
  来自随仓库固定的 GenOffice 构建产物，不是重新实现的一份。
- **编辑器外观跟 Mcode 主题走**：外壳用与 Mcode 相同的颜色 token；**文档内容**（纸张、单元格、
  图表配色、条件格式色）保持原样，不随主题改变 —— 那是文档数据，不是界面。
- 编辑器自己的 AI 面板与 API 配置**在宿主里不存在**：没有第二套模型、密钥或账号，
  避免两份计费与两份历史。文档里的 AI 一律经 Mcode 会话执行。
- 宿主工具栏提供「交给 Mcode AI」：把当前文件作为引用放进对话草稿，**不自动发送**，
  用户自己决定问什么。编辑器与对话并排显示。
- **保存冲突保护**：文件被别的程序或另一个窗口改过时，保存被拒绝并提示，不静默覆盖。
- **未保存状态**：关闭/切走标签时，有未保存改动的文档会先询问，不静默丢弃。
- **大文件提示**：超过 64 MiB 的文档打开时给一行提示（不阻止打开），因为编辑器本身就要
  100–250 MiB 内存，大文件会更慢更吃内存。
- **后台视图会被回收**：切走很久且没有未保存改动的编辑器，其渲染进程会被释放以省内存；
  切回来时自动重建。**有未保存改动的文档永不回收。**
- 能力缺失时（构建产物没装/缺原生依赖）**显式说明缺什么、怎么补**，不显示一张空白页。
- 设置 → 文档编辑器：一页看清六种格式在本机是否可用、AI 走哪条链、如何补齐。

**EDIT-05 PDF**
- 用 GenOffice 原厂 PDF 编辑器打开：文本层、页面编辑、批注、页面导航、格式导出。
- 不是「换成图片预览」—— 能编辑与导出才是本条的要求。

**EDIT-06 修订与复核（Overleaf 式）**

六种格式中，**文档、Markdown、表格、演示文稿、HTML 五种都有修订**；
**PDF 不做** —— 它的「改动」不是文本流上的编辑，而是叠加标注（批注、表单、涂黑、
签名），把「拒绝」实现成"删掉标注"和实现成"还原被改的文字"是两件事，混用会让左栏
的语义骗人。PDF 的标注走它自己的面板。

- **两种编辑模式**：编辑模式（改动直接生效）/ 复核模式（改动变成待审条目）。
  **AI 默认复核模式**；人用界面上的按钮切换自己的模式。人和 AI 走同一套机制，
  **只是颜色不同**（AI 一色、人一色）。
- **正文标记**：插入与删除在正文里按作者分色高亮；删除的文字显示删除线而不是消失。
- **左侧条目栏**：待审改动与评论都在**左栏**（AI 对话在右栏）。一条目对应一处改动；
  点条目跳到正文对应位置，点正文改动则高亮对应条目。**没有待处理事项时左栏隐藏。**
- **逐条接受/拒绝**：接受则文字并入正文、条目消失；拒绝则完全还原（新增的删掉、
  改动的还原、删除的恢复）。也可以选中一段文字批量处理，按钮上显示条数，执行前确认。
- **评论**：选中文字可以加评论；评论可编辑、可回复、可 resolve。resolve 后从主列表
  移到左上角入口（不是删除）——「这条当初为什么提」在复核场景里有价值。
- **颜色不区分身份**：人和 AI 用同一套机制，只靠颜色区分作者，不给 AI 单开一套流程。

**EDIT-07 选段引用**
- 在聊天消息、文件预览、编辑器（含 Monaco）里选中一段，都能引用给**任意一个代理**（带文件与行号）。

**EDIT-08 行内 AI 改写**
- 在编辑器里选中一段，直接说「改简洁点 / 翻成英文」，AI 只改这一段。
- 最终形态由上面的**编辑模式**决定：复核模式下变成待审条目，编辑模式下直接替换（可撤销）。

**EDIT-09 文件历史**
- 每个文件能查看以前的版本并回到某个版本，不依赖 git。

**EDIT-10 文档能力对 Agent 全面开放**
- **读**：docx 给块索引；xlsx 给**整本工作簿所有工作表**并标明哪些表没读到；
  pptx 给每页文本**与演讲者备注**；pdf 给每页文本。
- **写**：改文字、调格式、插表格/图片/图表、加批注、改页眉页脚等，走与原厂编辑器
  **同一条写入路径**，不另写一份解析器。
- **依赖实时上下文的能力**（当前选区、公式依赖图、批注线程）在文档开在 Mcode 里时
  必须可用；只把工具名列在目录里而执行不了，等于没有。
- **读取必须如实报告覆盖范围**：只读到部分内容时（表没读完、行被截断、文件过大），
  必须让模型知道「还有哪些没读」，不能把部分读当成整本。

**EDIT-11 评论可以交给 AI 处理**
- 能在文档里给某段写评论；评论可以交给 AI，按评论内容改文档。

**EDIT-12 GenOffice 云端能力整个不要**
- AI 生图、图片搜索、云端媒体分析 —— 属于 GenOffice 自己的账号与计费，Mcode 不转发。
- **UI 上的入口也要删掉**，不是留着然后点了报错。看不到这些按钮，是预期行为。
- 同类需求由 Mcode 自己的工具链承担。

## 七、工作流（WF）

> **工作流 = 一种工作方式**（像「文献精读」那样），在输入框左下角选中后正常发消息即按图执行，没有「运行」按钮。
> 多代理协作（包括「开会」、多个评审交叉评审）**用工作流搭出来**，不另做一套会议系统；工作流需要的话可以加新的节点类型。

**WF-01 图模型与编辑**
- 节点 + 连线。画布是 **Node-RED 原厂编辑器**（设置 → 工作流 → 引擎页；右栏也可停靠），
  拖拽、连线、节点属性面板都由它提供。
- **连线上没有独立标签**：原厂存储是 `node.wires[port][]`，边上不承载名称/说明。分支的
  「哪条出路叫什么」写在**分支节点自己的**出路说明里（`mcode-branch` 的 note / 目标标题），
  不假装原厂连线能存这个。
- 校验：普通工作流有且只有一个主代理节点；自动化至少有一个触发器；不合法的图保存时给出明确错误。
  这些校验在**宿主侧的保存闸门**上，不依赖编辑器。

**WF-02 节点类型**
- 画布是 Node-RED 原厂编辑器（设置 → 工作流 → 引擎页），节点类型以它为准。
- Mcode 自有节点：主代理（跑在主对话里，用户看得见）、子代理（跑在自己的会话里）、
  对话节点（跑在主对话里的一轮）、岔路口（用户选或模型判）、模块能力调用、事件触发器。
- 其余用原厂节点：条件判断用原生 `switch`，命令用原生 `exec`，代码是 `function`（JS）
  或 `exec` + 解释器前缀（Python / Shell / PowerShell），手动/定时/文件触发用原生
  `inject` / `watch`。
- 用户拖不到的内部节点（条件求值适配、Node-RED 引擎调用）仍能读、能跑，只是不进 palette。
- 插件可以注册自己的节点类型，第三方节点可以带自己的脚本。
- **插件节点类型在迁移时按 `loadNodeTypes()` 这张表映射**（内置 → 插件 → 本地，
  后者盖前者）。表里没有的类型不猜：节点照样迁移，类型改成 `mcode-unknown`
  并保留原始 type，报告里逐条点名 —— 一份别处分享来的图引用了本机没装的类型时，
  用户看到的是一句明确的"这个类型没装"，而不是一个跑不起来的空节点。

**WF-03 调度**
- 图的执行由 Node-RED 运行时负责；Mcode 只提供节点执行体与权限。
- 命令非零退出码不算流程失败。
- 宿主侧限制并发与取消的语义以 Node-RED 为准；Mcode 额外提供：
  执行归属（一张图同一时刻只有一个执行者）、手动运行时的防重入、以及引擎停止时把
  未完成运行收成「已取消」。
- **能力预检只在宿主发起时做**（手动运行、`automation.preflight`）。**引擎自己触发的
  运行不做同步预检** —— Node-RED 的 inject/watch 由引擎调度，宿主没有"触发前拦一下"
  的钩子。硬做只能靠轮询或改引擎源码，两者都比"跑起来之后那一步明确失败"更糟。
  要走预检就在部署前用 `automation.preflight` 查一遍，或在自动化面板里点「立刻运行」。

**WF-04 变量**
- 节点有产出变量，下游用 `{{某步.某变量}}` 引用；自动化的触发载荷用 `{{trigger.*}}` 引用；引用不到时这一步明确失败并说明原因。
- **命令节点的 shell 正文例外**：不允许动态插值。命令固定，用户输入、触发载荷与上游数据通过已有 JSON 标准输入传给脚本；旧写法明确提示迁移，不自动改写用户自定义工作流。

**WF-05 进度与结果**
- 画布上运行中的节点有**状态行**（执行中 · 耗时秒数，成功/失败各自可辨）。这是 Node-RED
  原生的 `node.status` 机制；旧手写画布的「沿边框走亮线」随该画布删除一并退场。
- 节点上另有**能力徽标**（只读/可写/可执行/可联网），只读展示，不代表权限 ——
  真正的判定在宿主侧。
- **不做「画布上的待审查徽标」**：审查状态由**运行入口**把关（未通过审查的图不启动，
  并在入口处说明原因），而不是在画布上挂一个标记。挂一个只在某个视图里可见的徽标，
  会让人以为"没徽标 = 已审查"，而真正的判定从来不看它。
- 对话里每步一张结果卡，同一步多轮时原地换成最新一版；卡上能看过程、产出、token 与花费。
- 看板面板列出各节点卡片与子代理。

**WF-06 断点续跑与重试**
- 运行史持久保存：每次原生运行都会在库里留下记录（开始/结束、每步结局）。
- 失败后可以重跑：入口是运行卡片上的「再试一次」。**原生图的重试是整条流重跑**，
  不是「从失败那一步连同下游」—— Node-RED 的消息流不持久化「执行到哪一格」，上游也
  没有「从某节点重入」的公开入口。定时/文件/事件驱动的图没有手动触发器，要先加一个。
- **崩溃后从停下处接着跑：当前不支持，如实不做承诺。** 这需要给 Node-RED 的消息流补
  一套持久 journal，是上游没有的机制；不做不会伪装成做了。
- 工作流图在运行后被改过时，拒绝用旧状态续跑并说明原因；中断时可能已产生副作用的节点不自动重放，提示用户核对。

**WF-07 与节点对话**
- 子代理节点自动认回自己的会话，身份是 `(工作流, 节点)`：同一张图的同一格，无论被触发
  多少次，都落在同一个会话里，上下文保留。
- 节点属性里显式填写的「Mcode 会话 ID」优先；填了就用那一条，找不到就报错，不退回自动分配。
- **对话节点必须显式绑定一条用户看得见的对话** —— 它的语义就是「跑在用户正在看的那个
  对话里」，自动建一条隐藏会话等于把这个语义悄悄换掉。
- 每个代理每轮都知道整条流程和自己所处的阶段。
- **把话递进某条对话而不等回答**：对话节点上的 `injectMode: "auto"` —— 消息投进目标
  对话后流程立刻往下走，不卡在那条对话的回答上。⚠️ 这一步拿不到那轮的产出。
  （旧路径叫「递给主代理」，原生侧没有"发起会话"这个概念，所以目标是**节点上显式绑定的**
  那条对话，不是一个隐式的"发起人"。）

**WF-08 代理档案**
- 可定义代理档案：**一份节点参数预设**（对 `mcode.agent` 来说就是指令、模型、引擎、
  能力这些参数），从插入菜单直接按档案建节点，也可把当前节点的参数存成一份档案。
- **档案是参数，不是独立实体**：套用档案的那一刻，参数就写进节点了 —— 之后改档案
  不会回头改已经建好的节点（反过来做的话，用户改一次档案会波及所有历史节点）。
  所以"档案在原生路径是否生效"这个问题本身不成立：原生侧读的就是节点参数。
- **档案不含记忆注入**：记忆是节点自己的参数（`memory`），与档案是两个独立的开关。
  把记忆塞进档案会让"套用一次档案"意外改变那条会话的长期行为。

**WF-09 管理**
- 工作流列表：新建、复制、删除、导入、导出、设为默认、恢复默认。
- 导入的或 AI 修改过的工作流，在用户审查并启用之前不能运行。
- 工作流级「框架说明」会拼进每个节点的提示词。
- **旧图迁移**：启动时把库里还挂在旧执行器上的图自动迁到 Node-RED（逐张判 SAFE /
  需要人工 / 拒绝），结果写进日志；迁不动的留在库里仍可打开，但不会执行。
- **旧执行器已退场**：任何仍归旧执行器的**用户图**都不会被运行。四个入口给的是
  **同一句话**（手动运行、钩子的工作流动作、自动化手动跑、自定义界面的"运行自动化"），
  说明这张图需要迁移、迁移入口在哪。
- **内置编排不在此列**：记忆整理的三张内置图归 Node-RED 执行（见 MEM-04），不是用户
  工作流。旧执行器的代码保留，只为承载尚未迁完的内部路径。

## 八、自动化（AUTO）

> **自动化 = 后台自动跑**（像 cron / 文件监听），入口在设置 → 自动化，有「立刻运行一次」按钮。
>
> **前提（Q8，2026-10-27 实装）**：图由 Node-RED 引擎执行，而引擎是一个子进程。应用启动时
> 只要库里存在任何归 Node-RED 的图，就把引擎拉起来（没有这样的图不启动，不为用不到的
> 功能付内存）。引擎起来了但 flow 未获信任时 `safeMode` 仍然开着 —— 那种情况下图能编辑、
> 能看，但**不会自动执行**，界面上会明确写出这一点。

**AUTO-01 触发器**
- 手动、定时（cron）、文件变化（带防抖）、事件（挂在钩子事件表上，如「条目入库」「PDF 下载完成」「一轮结束」）四种。
- **四种都由 Node-RED 引擎侧执行**，映射到原厂节点：手动/定时 → `inject`（cron 原样写成
  `crontab`）、文件变化 → `watch`、事件 → Mcode 的 `mcode-trigger`（订阅与「钩子」同一份
  事件流）。迁移时 `debounceMs` / `excludePaths` / 项目 id 这些原厂节点不表达的字段保留在
  节点参数里，并如实标为 lossy。
- 每个触发器可单独启用/关闭；关闭只挡自动触发，手动运行照跑。**手动运行也走引擎**
  （「立刻运行一次」、右键「运行自动化」、手机端都转发到同一个入口）。

**AUTO-02 运行与记录**
- 同一个自动化运行中时再次触发会跳过（防重入）。
- 仪表盘按触发器显示：是否已挂上 / 已关闭 / 没挂上（坏了）、运行状态、最近一次、报错；有运行历史。
- 应用没开时错过的定时会记录为「错过」。
- **重启后自动恢复的授权**：引擎是否在下次启动时自动执行已部署的流，由宿主的信任标记
  决定（`engine-trust.json`）。写这个标记的唯一路径是**用户审查**：库里所有归 Node-RED
  的图都审查通过才写，任何一张待审就撤销。没有第二条绕过入口，Agent 不能替用户批。

**AUTO-03 内置自动化示例**
- 提供「新条目入库后自动下载」「PDF 到位后自动转 Markdown」等示例，可删除、可修改。

## 九、钩子、技能、MCP、插件（EXT）

**EXT-01 钩子**
- 在事件发生时运行用户自己的命令。事件覆盖一轮的生命周期：发消息、工具调用、工具结果、等待审批、审批/提问被回答、提问、计划待批、待办变化、子代理变化、改动文件、一轮未完成、一轮结束、上下文压缩、出错、上游重试、工作流节点完成、条目入库、PDF 下载完成。
- 可按工具名/文件路径匹配；每次执行有记录（标明是本次启动以来的记录）。
- 三种动作：命令、Agent 档案、运行一张工作流。**运行工作流走 Node-RED 引擎**：
  那张图必须有已部署的手动触发器（钩子事件不是它自己的触发器，替它点火会绕过图的
  触发语义）；图还挂在旧执行器上时明确拒绝并指路。

**EXT-02 技能**
- 管理 SKILL.md 技能：**一页三栏**（总库 / 项目 / 节点），自带编辑器；技能可作为斜杠命令使用，可预设。
- **跨项目总览不单开页签**，它就在「项目」栏里 —— 用户看项目级技能时往往同时想知道
  "别的项目装了什么"，为它多开一个页签要来回切。「节点」栏管的是节点级技能预设。

**EXT-03 MCP 服务器管理**
- 添加/编辑/删除/启停 MCP 服务器（stdio / http / sse），可指定给哪些引擎用；http 类支持 OAuth。
- 能检测服务器是否连得上（命令不存在、起不来时要告诉用户）。

**EXT-04 插件（大模型插件）**
- 支持安装大模型插件：一个包里可以带技能、MCP 服务器、工作流节点类型；全局安装/启用，工作流可逐轮指定。
- 不做类似 DeepSeek Harness 那种「一切皆插件」的应用插件内核；应用界面的自定义由「自定义界面」（EXT-05）负责。

**EXT-05 自定义界面**
- 主界面上的挂载位：资料库四级右键（条目 / 分类 / 小类 / 大类）、文件右键、消息右键、选中文字、会话右键、右栏页签、主页面与右栏之间的竖向工具栏。
- 每个挂载位可以：显示/隐藏、排序内置项；添加自定义项（名字 + 图标 + 显示条件 + 动作）。
- 动作是声明式的：打开视图（Markdown 模板）、发给对话（提示词模板）、复制文本、运行自动化、打开文件、切到右栏某页签。
- 可以添加自定义面板（HTML，在严格隔离的沙箱里运行，不能联网、不能执行任意代码）。
- 管理类菜单项（重命名、移动、删除、新建分类等）固定，不可隐藏。

**EXT-06 Mcode 自身的工具（给本地三个引擎用）**
- 三个本地引擎可以通过工具操作 Mcode 自己的功能：一个通用的「先列出、再调用」通道覆盖全部功能，加上常用功能的专用工具。
- **三个引擎各用各的挂载方式，但工具表是同一份**（`main/appControl/tools.ts`）：
  Claude 走进程内 MCP server `mcode-app`（`main/mcp/appServer.ts`），
  Codex 与 Pi 走各自的动态工具表（`appToolDescriptors`）。**换引擎不换能力**。
- 危险操作每次都要用户批准，不允许「总是允许」；API Key 与令牌不返回给模型。

**EXT-07 VS Code 扩展（唯一的扩展系统）**
- 装 `.vsix`，跑真实的 VS Code 扩展。**一个扩展系统**：不再有并列的第二套扩展机制。
- 复用 VS Code 协议与生态：Theia plugin host 提供 `vscode.*` API，扩展按原样写、按原样跑。
- 装进来之后**能装上就能跑**：允许扩展执行外部命令（`child_process`）。这是明确的取舍 —— 宿主不是沙箱，
  安装时告知用户在装什么，之后不打断。
- 装上、启用/禁用、启动/停止、卸载、改配置；同时运行多个扩展，各自一个会话。
- 扩展的 UI 贡献落到 Mcode 自己的界面：状态栏、命令面板、快捷输入、通知、诊断、Webview、
  自定义编辑器、语言能力（补全/悬停/跳转/引用/符号/格式化/重命名/代码动作）。
- 扩展能调用 Mcode 的全部功能：`vscode.commands.executeCommand("mcode.<方法名>", 入参)`。
  覆盖工作流、资料库、记忆、会话、文件等所有对扩展开放的能力；新增 Mcode 功能不需要改扩展侧代码。
- 权限沿用既有分档：只读直接执行；写与高风险每次要用户批准；密钥类操作（拿 API Key、自授权）扩展够不到。
- `vendor/theia` 是独立检出（A′ 模式，不进本仓库 git，身份由 `vendor/theia.lock.json` 钉住）。
  克隆后按 `vendor/README.md` 构建一次即可运行扩展宿主；打包时由
  `build/stage-theia-resources.cjs` 装配出最小运行集（实测约 10 MiB）随安装包分发。

## 十、记忆与上下文（MEM）

**MEM-01 记忆库**
- 跨会话记住规则、偏好、经验、决定等（分类目存为可直接编辑的 Markdown 文件），分全局与项目两级。

**MEM-02 注入**
- 每轮按相关性检索记忆注入给模型；能预览「这一轮会注入什么」。

**MEM-03 模型写记忆**
- 模型能通过工具写入/检索/遗忘记忆；工具说明要求不记敏感信息。

**MEM-04 维护**
- 能查看、编辑、删除记忆；「整理记忆」找出过期或重复的条目，由用户确认后清理（不自动删除）。
- 「整理记忆」是记忆库的功能，**不是工作流功能**：它内部用三张 Mcode 内置图
  （`memory-capture` / `memory-checkpoint` / `memory-health`）组织多步流程，这三张图
  与用户工作流一样归 Node-RED 执行。引擎没起或那几张图没部署时，按钮给出可照做的说明，
  不回退到旧执行器。

**MEM-05 导入导出**
- 记忆可以导出、导入（迁移到另一台机器）。

**MEM-06 项目初始化**
- 在设置 → 记忆与上下文 →「项目初始化」页签里管理初始化方案（自定义要生成的文件 / 目录 / 项目记忆）；每个方案成为 `/init-名称` 命令。
- 执行时：预览后确认、不覆盖已有文件、作用于会话当前项目（含 worktree）。

## 十一、手机远程（MOB）

**MOB-01 连接方式**
- 局域网内扫码配对。
- 外网：用户自己运行 cloudflared（快速隧道或自有域名），Mcode 显示本地地址和需要的配置；Mcode 不托管隧道令牌。
- 手机远程连接与设置里的「远程控制（MCP）」开关**互相独立**，不需要打开那个开关。

**MOB-02 登录**
- 手机端用账号 + 密码登录；设备可在电脑上查看与吊销。

**MOB-03 手机上能做的事**
- 看会话列表与对话、搜索会话、发消息、批准/拒绝操作、回答提问、看文件（**只读**）、
  看 Git 状态并提交/推送；部分设置（语言、强调色、快捷命令等）在电脑和手机之间同步。
- **文件写操作刻意不在手机上开放**（新建/改名/删除/复制/写内容）。这不是没做，
  是边界：手机上误触一个"删除"没有回收站可退，而"往这台电脑的工作区里写文件"
  是应当由本人在桌面上做的动作。终端同理 —— 手机只给只读的终端列表。

**MOB-04 连接手机对话框**
- 固定高度，内容在内部滚动。

## 十二、对外 MCP 端点（PUB）

**PUB-01 公网 MCP**
- 可以开一个公网 MCP 端点（链接里带密钥），让网页版 AI（如 ChatGPT 网页版）调用 Mcode 的工具；可配置多个项目。

**PUB-02 开放的能力**
- 资料库：**只读**浏览与检索。
- 本地技能与工具：读写项目文件、执行命令、进程、SSH 与远程任务、读文档/图片等。
- 根据使用者类型给出对应的使用说明。

**PUB-03 不开放的能力**
- 不提供工作流 / 自动化工具；不暴露会话记录与代理信件工具；不返回任何密钥。
- 写文件、执行命令等操作需要用户在 Mcode 里确认。

## 十三、设置与系统（SYS）

**SYS-01 设置页**
- 至少包含：通用、外观、自定义模型、引擎/运行时、插件、技能、工作流、自动化、钩子、MCP、记忆与上下文、语音、快捷键、手势、通知、资料库类型、自定义界面、机构访问、Git、终端、浏览器、语言服务、运行策略（预算/回退）、监控、用量、关于。

**SYS-02 外观**
- 主题、强调色、字号可调；手绘风格等主题样式；修改即时生效。

**SYS-03 快捷键与手势**
- 快捷键可自定义（录制），冲突时提示；鼠标手势（按住右键拖动）可录制并绑定到与快捷键同一套命令。

**SYS-04 通知**
- 需要审批/提问/计划待批、回合完成、出错、后台任务完成时通知，可按类别开关；应用失焦时用系统通知，聚焦时用应用内提示；未读事件在会话列表和标签栏显示角标；可开提示音。

**SYS-05 语音输入**
- 使用本地识别模型，不上传音频；可在设置里下载/切换模型。

**SYS-06 监控与用量**
- 监控页：后台运行（工作流、自动化）的概览与历史。
- 用量页：统计 token 与花费（按时间、模型等维度），每轮的用量记录重启后仍在。

**SYS-07 数据目录**
- 会话、资料库、模版、工作流、记忆都放在同一个数据目录下，可在设置里查看与迁移。

**SYS-08 更新**
- 应用自动检查更新，也可在「关于」里手动检查；有新版时提示下载安装。

**SYS-09 首页**
- 没有打开会话时显示「开始一件事」：接着聊、用工作流开始、最近加入的资料、正在守着的自动化；没内容的块不显示。

**SYS-10 命令面板**
- Ctrl+K 打开，能搜索会话、文件、资料库文档、命令。

**SYS-11 安装包**
- Windows：按用户安装的 `.exe`，不需要管理员权限；同时提供 macOS `.dmg`（不作为检查重点）。
