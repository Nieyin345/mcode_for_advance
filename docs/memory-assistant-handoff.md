# 主页面记忆助手与临时对话交接

## 本轮实现

入口在桌面主页面的聊天输入区工具栏：**记忆助手**。无需进入设置，也不切换当前聊天的工作流。

三个操作现在是带 `manual` 触发器的后台自动化，使用既有图执行器、节点会话、审批和运行记录，不新建执行引擎：

| 操作 | AI 做什么 | 结果放在哪里 |
|---|---|---|
| 帮我记住重要内容 | 提取候选、核实查重，经宿主逐条审批保存 | 长期知识默认进入当前项目的统一 Markdown 记忆库；全局共享需明确确认 |
| 交给另一个对话继续 | 整理目标、限制、进度、证据、未知事项和下一步 | 独立的临时交接记录，不进入长期记忆库 |
| 检查已有记忆 | 检查当前项目与显式全局的疑似重复、冲突和适用条件变化 | 生成维护报告，不自动删除 |

本轮同时补上了前一轮遗漏的内置注册表接入，并增加实际注册表、IPC 注册及真实 runner 的测试，而不再只验证模板自身。

## 临时交接怎么用

1. 在原对话点“记忆助手”→“交给另一个对话继续”。
2. 专门 AI 在后台整理，不借用原对话的提供方历史。每次运行创建新的自动化和节点上下文。
3. 在结果区预览交接材料，选择同项目已有对话，或保留默认“创建同项目的新对话”。
4. 点“交接并打开目标对话”。这一步不会自动运行原任务，也不会恢复旧执行进程。
5. 在目标对话发送“请继续”或其他明确要求；下一轮会附带临时交接材料。目标页面的“有待接收的交接材料”入口可以预览内容。
6. 只有目标模型回合以 `end_turn` 成功结束才确认消费。失败、中断、工具阶段停止和输出达到上限都保留有效期内的包，允许重试。
7. 成功消费后清除待投递正文，后续新轮次不再自动注入该包。

已发送进模型上下文的内容不能由“清理交接包”倒过来擦除。原对话、原运行记录及提供方历史仍按既有机制留存；清除这里的整理结果也不撤销已经批准的长期记忆写入。

## 存放与生命周期

- 临时交接和助手任务元数据复用现有应用数据库的 settings 存储，使用 `memory.assistant.*` 命名空间；不是项目代码目录里的文件，也不是长期 Markdown 记忆。
- 每个来源对话保留最近最多20项入口记录；结果默认7天有效，读取时对过期正文执行清理。过期检查不是独立定时清理器，不承诺到期瞬间物理擦除所有副本。
- 正式运行记录继续由既有 runStore 保存，便于回查证据；它不会因此成为共享长期记忆。
- 等待目标接收的交接包和绑定关系可跨应用重启保留。中断的整理任务不会偷偷重新运行；失去执行者的任务标记失败，用户决定是否重新发起。
- 重复点击同一交接包不会反复创建新对话；同一目标不能被另一份包静默覆盖。
- 同项目、来源归属、目标会话种类、包种类及状态均在宿主验证，不只依赖界面筛选。
- 已进入目标执行回合时，不允许假装撤回已经发送的上下文。需要停止时先中止目标回合。
- 停止整理也覆盖引擎预检阶段，避免点击停止后模型才开始运行。

## 默认范围与权限

- 使用当前对话选定的引擎和模型，正常模型用量会计费。
- 整理材料来自当前对话最近最多48条已保存消息，以及关联最近3次运行；不默认扫描其他聊天。
- 文本预算约32000字符，优先保留较新的消息；图片、思考块和任意完整工具参数不作为原始 JSON 整包发送。已知形式的疑似密钥会遮蔽，但这不是完备的敏感信息识别系统。
- 输出必须说明未覆盖、未核实的部分；不是“48条足以完整理解任意任务”的保证。
- AI 的提问和工具审批通过宿主的交互代理链回到原主页面，不挂在不可见后台会话中。普通无人值守自动化的拒绝审批规则不因此放开。
- “检查已有记忆”的只读目标来自模板约束；长期记忆修改仍须经过原有宿主审批。通用文件／Shell 工具没有新增沙箱，不能把提示词约束当成权限隔离。
- 不新增定时监听、记忆修改后自触发或全项目自动扫描。需要当前对话材料的这些模板应从主页面助手入口启动；工作流库中未绑定项目的通用“立即运行”入口不能替代来源对话选择。

## 本轮验证关注点

使用隔离 SQLite 和假提供方，不调用真实模型。新增覆盖：

- 三个自动化真实注册、触发器契约与实际 IPC 注册；
- 一次点击通过真实 runner 启动独立后台节点，来源聊天的工作流保持不变；
- 当前消息、关联运行证据的真实输入构造，历史范围限制、图片及明显密钥排除；
- 临时包待投递、重复投递、跨项目拒绝、来源伪造拒绝、覆盖拒绝、撤销、到期、消费后正文清除；
- 非成功回合不消费，过时回执不消费另一个包；
- 两个持久记录之间中断后的指针修复；
- 重启后不自动重放、再次整理使用新上下文、引擎预检期间取消；
- 后台节点到原对话的多级审批路由与循环保护。

真实三引擎执行、桌面 GUI 点击与审批互动尚未验收。应用崩溃与远端请求之间不具备分布式 exactly-once 保证；这里采用保守保留、成功回执消费及幂等绑定，而不宣称绝对不重放。
