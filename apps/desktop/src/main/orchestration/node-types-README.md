# 工作流节点类型

这个目录放**节点类型**的定义 —— 工作流图上一个格子"能干什么、要填什么"就写在这里。
文件名随你起,内容是 JSON。

> ⚠️ 这个目录**只认 `.json`**。它是**数据,不是代码**:这里的东西不会被 import、不会
> 被执行。想带脚本,用 `runner.entry` 指一个相对本文件的路径(见下面的「执行方式」)。

---

## 最小的一个例子

```json
{
  "id": "myorg.word-count",
  "manifestVersion": 1,
  "name": "统计字数",
  "description": "读一个文件,数出中文字数。",
  "icon": "book",
  "category": "文本",
  "capability": "read",
  "runner": { "kind": "command", "entry": "./count.py", "interpreter": "python" },
  "params": [
    { "key": "input", "kind": "file", "label": "输入文件", "required": true,
      "bind": { "kind": "arg", "flag": "--input" } }
  ]
}
```

---

## 字段

必填的是 `id` / `manifestVersion` / `name` / `runner` / `capability` / `params`
(没有参数就写 `"params": []`)。

| 字段 | 说明 |
|---|---|
| `id` | 见下 |
| `manifestVersion` | 现在**只能是 `1`** |
| `name` | 显示名 |
| `description` | 一句话说明 |
| `icon` | 图标键。认不出的键会回落成通用图标,不会报错 |
| `category` | "添加节点"菜单里的分组。不写归入「其他」 |
| `capability` | `read` / `write` / `exec` / `net`。**这是默认值**,单个节点可以覆盖 |
| `runner` | 见「执行方式」 |
| `params` | 见「参数」 |
| `outputs` | 可选。声明产出什么,纯说明:`[{ "key": "summary", "label": "结果" }]` |
| `usage` | 可选。**写给模型看的一句话**:什么时候用它。会进系统提示词 |
| `doc` | 可选。相对本文档目录的 markdown 路径 |

### id

- 形状是 `作者.名字`,**两段**,都小写、用连字符分词:`myorg.word-count`。
- **`mcode.` 是内置类型保留的前缀,你不能用。** 想改内置节点的行为,起你自己的 id ——
  这样别人分享给你的工作流里写 `mcode.agent` 时,在哪台机器上指的都是同一个东西。

## 参数

每个参数在画布上会渲染成一个控件,值存在节点的 `params` 里。

| 字段 | 说明 |
|---|---|
| `key` | 在 `params` 里的键。字母开头,字母数字下划线 |
| `kind` | `text` / `longtext` / `number` / `boolean` / `select` / `file` / `dir` / `model` |
| `label` | 画布上的字段名 |
| `help` | 可选。字段下面的一行说明 |
| `required` | 必填。必填项没填,图**存不下去**(会当场报错,不会等到执行) |
| `default` | 新节点的初始值 |
| `options` | `select` 专用:`[{ "value": "a", "label": "甲" }]` |
| `bind` | 见下。**只有 `command` 类节点用得上** |

### bind:参数怎么送到脚本手上

**不要在命令里拼字符串。** 声明"这个参数绑到哪个位置",由 Mcode 拼参数数组 ——
值永远是一个独立的参数,不会被 shell 解析:

```json
{ "kind": "arg", "flag": "--input" }
```
→ 追加 `--input <值>` 两个参数。`flag` 省略 = 位置参数。

```json
{ "kind": "env", "name": "INPUT_FILE" }
```
→ 环境变量 `INPUT_FILE=<值>`。名字必须大写、下划线分词。

```json
{ "kind": "stdin" }
```
→ 写到进程的 stdin。**最多一个参数能这样。**

## 执行方式

`runner.kind` 只有四个值 —— 这是 **Mcode 保留的执行原语**,你不能自己发明新的:

| kind | 形状 | 现在能用吗 |
|---|---|---|
| `prompt` | `{ "kind": "prompt" }` | ✅ 一个带独立指令的子 agent,跑一轮对话(**另开一段会话**) |
| `conversation` | `{ "kind": "conversation" }` | ✅ 同样跑一轮模型,但**跑在主对话里**(内置的主代理与对话节点都是这一种,见下面「对话节点」) |
| `branch` | `{ "kind": "branch" }` | ✅ 岔路口:不跑东西,把决定权交给用户(见下面「出路」) |
| `command`(命令进**参数**) | `{ "kind": "command" }` | ✅ **能跑** —— 内置的 `mcode.command` 就是这个形状:命令写在节点参数里,本机起进程跑 |
| `command`(命令进**自带脚本**) | `{ "kind": "command", "entry": "./x.py", "interpreter": "python", "args": [] }` | ❌ **形状定好了,执行还没实现** |
| `code` | `{ "kind": "code", "language": "python" }` | ✅ 能用 —— 内置的 `mcode.code`,写一段脚本跑,产出 `exitCode`/`stdout`/`stderr` |

`command` 的 `entry` 是**相对本文档所在目录**的路径,逃出这个目录的路径会被拒绝。

> ⚠️ **注意区分两种 command**:
>
> - **命令写在参数里的**(`{"kind":"command"}`,内置 `mcode.command`)—— ✅ **能画、能存、能跑**。
> - **命令来自自带脚本的**(`entry` 填了,第三方插件那种)—— 能画、能存,但**跑不了**;
>   画布上会明确标出来,执行时也会明确报错,不会假装跑过。**要把脚本干的活写进「命令」参数里。**
>
> 判定这件事的**唯一函数**是 `isNodeRunnable`(见 `contracts/src/nodeType.ts`)—— 
> 调度器的拒绝与渲染端的徽标读的都是它,不要只看 `runner.kind` 自己判。

### 对话节点:不隔离的那一种

`prompt` 节点是**新开一段会话**,它只知道你写在指令里的那些东西 —— 主对话里聊过什么,
它一个字都看不到。那是刻意的隔离:节点不会跑偏、可以重复跑、一张图分享给别人也照样
跑得起来(别人拿到你的图,可没有你那半小时的聊天记录)。

但有些步骤**恰恰需要那段聊天**:「按刚才定的思路改第三章」。所以有 `conversation`
—— 内置的 **`mcode.main`(主代理)与 `mcode.conversation`(对话节点)都是这一种**:

| | `prompt`(子 agent) | `conversation`(主代理 / 对话节点) |
|---|---|---|
| 在哪儿跑 | 新开一段隐藏会话 | **就在主对话里** |
| 知道之前聊过什么 | 不知道 | 知道(全部) |
| 收到上游产出 / 按表交东西 | 能 | **能**(这一组两边共用) |
| 产出落在哪 | 回图里,由下游取 | 图里能取,**同时**留在对话里 |
| 能换引擎 / 限技能 / 换模型 | 能 | 不能 —— 用主对话当前那一套 |
| 能配「回到主对话」 | 能(见下一节) | 不用配 —— 它本来就在那儿 |
| 有「看过程」入口 | 有 | 没有(过程就是聊天本身) |
| 上下文 | 一步一清 | **只增不减**,永久留在主对话里 |

图上**唯一一处两样的地方是回声**:对话节点的那段指令是"一句用户会说的话",聊天框里
看得见它;而**入口节点(主代理)拿到的提示词是代码拼的脚手架**(流程位置 + 用户的请求
+ 产出要求),所以它**不回声** —— 用户自己打的那句原话由调度器回声,聊天框里正好一条。
模型读到的仍然是完整的那一段,一个字不少。

拿它做什么:**需要用到当前讨论的步骤**。别把一张长流程的每一步都设成它 —— 那会把主
对话撑得很大,而每一步读过的文件、工具的每一次返回都会一直背着。

它在跑的时候这个对话是**被占住**的,你插不进话;而且它跑完**不会**让界面显示"这一轮
结束了",那条要等整张图收尾。

### 回到主对话:隔离节点怎么把东西交回聊天

子 agent 是另开一段会话,它做的事**主对话一个字都不知道**。有时候这不合适 ——「这一
步查出来的那几张表,后面我还想接着聊」。`returnToChat` 就是管这件事的一个开关:

| 值 | 并回去的是什么 |
|---|---|
| `none`(默认) | 什么都不并 —— 这一步只回图里 |
| `result` | **只有结论**:这一步最后说的话 |
| `full` | **结论 + 过程**:它说过的话,加上它调了哪些工具(工具名 + 一句参数摘要) |

**并进去的东西下一轮才生效。** 它不是往聊天记录里插一条消息,而是在你下一次说话时
**接在那句话前面**一起发给主对话 —— 并且明说了那是「刚才跑的工作流留下的东西,**不是
用户刚说的话**」,免得助手把它当成你的新指令。

`full` 那档的过程**有长度上限**(超了会截掉并说明)。理由不是省事:并进去的内容会
**永久留在主对话的上下文里**,每一轮都要重发一遍 —— 不设上限等于让某一次节点运行把
之后每一次对话的成本都抬高一点。所以默认是 `none`,`result` 是常用档,`full` 留给
"我确实要看它怎么查的"。

⚠️ 它和方法里的另一件事**不是一回事**:节点之间传结果走的是**图**(上游产出自动接在
指令前面,或者用 `{{某步.output}}` 点名),那条路一步一清、不影响主对话。`returnToChat`
管的是**图 → 聊天**这一个方向。

## 出路:边可以是一条岔路

一个 `branch` 节点**不产生任何东西**,它做的是**停在那儿问用户走哪条路**。它的选项
**就是它的出边** —— 图上有几根线,就是几个选项:

```
[子 agent:评审] ──> [分支:下一步做什么] ──[再来一轮]──> [子 agent:写作②]
                                       └──[进查重]───> [子 agent:查重]
```

用户点了哪条,哪条继续跑;其余几条**连同它们拖着的整条支路**一起作废(那些步骤在
对话里标成「**没走这条路**」,和「上游失败」是两句不同的话)。

两条边可以带的字段:

| 字段 | 是什么 | 给谁看 |
|---|---|---|
| `label` | 这个选项叫什么(`再来一轮`) | **用户**,在选择按钮上。留空就用目标节点的标题 |
| `note` | 选了这条之后,给下一步的一句说明 | **模型**,拼进下一步的提示词 |

**选项住在边上,而不是节点上的一张表里。** 一张表会有两种真相:表里填了三个选项、图上
只拉了两根线,而"用户能选什么"该读哪一份就说不清了。住在边上不会有这个问题 —— 每个
选项必然通向某一步,也不存在一根"说不出自己是什么"的线。

> ⚠️ 一对节点之间**只可能有一条边**(边的 id 由两端算出来)。所以一个分支节点不能把两个
> 选项指向同一步;那种情况下那两个选项本来也该是**两个节点**。

**走到下一步时它看得见用户选了什么。** 那一步的提示词里会多出一段:

```
## 本次执行的前置选择
上一处分支「下一步做什么」中,用户选择的是「再来一轮」。
<那条边上的 note>
用户补充说明:<用户在选择时临时写的话>
```

三样东西的详略是刻意的:选了什么(一句)、那条边的作者说明(画图时就写好的)、用户
此刻临时说的(只对这一次成立,常常没有)。

⚠️ **这一步如果打开了「读流程记录」,这一段就不单独出现** —— 那次选择已经作为一条
日志写进记录里了(见下面「回头」那一节)。两处都写就是同一件事说两遍。

**未选中的那一条不当"失败"传。** 分支之后两条支路常常在同一个汇合点碰头(上面那个例子
里「再来一轮」和「进查重」最后都会走到「导出」),用户选了一条之后,**汇合点照跑** ——
调度器把没走的那条当作"不存在",而不是"失败了"。失败会传染,没走不会。

### 回头:一条线指回前面

一条出路可以**指回前面某一步**,那就是"这几步再来一轮":

```
[子 agent:成稿] ──> [分支:稿子怎么样] ──[再改一轮]──┐
        ↑                                          │
        └──────────────────────────────────────────┘
                       └──[就这样,定稿]──> [子 agent:定稿]
```

**停得下来,因为绕一圈必须经过那个岔路口**,而岔路口要用户点一下 —— 这是结构上成立的,
不是靠"最多 N 轮"的计数器兜着。所以:

- **环上必须有一个分支节点。** 没有的话存盘就会被拒(「图里有环」),因为那是一个没有
  人拦着的死循环。图里**别处**有分支不算 —— 闸门必须在**这一圈**上。
- **绕几轮由用户决定**,不写死在图里。想再改一轮就再点一次「再改一轮」。

**环上的步骤默认打开「读流程记录」**(见下),所以它重跑时看得见整条流程做过什么 ——
包括它自己上一版。它每次跑都是一个新的会话,不记得上一版;上一版是从**记录**里来的。

### 读流程记录:让一步看见整条流程

默认情况下,一个节点只看到**直接上游**的产出。节点上的「**读流程记录**」开关打开之后,
它看到的是这条流程至今的**日志**:

```
## 流程记录
**本流程**:文献写作 —— 先核实每一条引用确实存在,再落笔成稿;成稿之后由用户决定是再改一轮,还是就此定稿。
**用户最初的要求**:帮我写下我那篇论文的引言

以下是本流程至今各步骤的产出,按完成的先后排列。

### 明确写什么
《引言》第一节,投稿用的中文期刊论文,600 字左右……

### 核对引用
- 可引文献:[1] 张三, 李四. 星地量子密钥分发中的波长优化. 物理学报, 2023. DOI: ...
- 没核到的:用户提到的「2024 年 Nature Photonics 那篇综述」库里没有

### 用户的选择
在「稿子怎么样」处选择「再改一轮」。
用户补充说明:第三章太啰嗦,删掉一半。

### 成稿(第 2 轮)
## 引言
星地量子密钥分发(satellite QKD)近年来……(正文全文)
```

四条规矩:

- **开头永远是这条流程本身**(叫什么、是干什么的)+ 用户最初的要求。缺了它,一串产出
  看不出它们凑在一起是为了什么。
- **有产出变量的步骤按变量名展开**(`- 可引文献:…`),没有的给整段原文。JSON 的花括号
  和引号是给机器读的形状,而读这段的是模型 —— 展开之后它读到的词和它自己指令里写的一模一样。
- **每个步骤只留最新一版**,重跑时旧的那条被换掉并排到末尾。所以记录的大小**与轮数无关**;
  而"完成先后"这个顺序让"我在第一版之后被要求改了第三章"读得出来。
- **用户历次的选择一条都不删。** 它们是历史,而"用户一共要求过什么"是迭代里唯一不会
  过期的信息 —— 少了它,第三轮会照着自己的想法把第一轮被否掉的东西再做一遍。

**默认值按图的结构给:在环上的步骤默认打开。** 环是"要迭代"的唯一信号,而迭代那一步
最需要知道前面做过什么 —— 这样用户不必先知道有这么个开关存在。想改就改,改过之后以
他写的为准。

**打开会让上下文明显变长**(它是全程而不只是上游),所以不需要的步骤不要开。

## 一个 prompt 节点拿到什么

`prompt` 类的节点跑起来时,喂给它的那一段是**拼出来的**。规则只有两条,但**第二条
会咬人**,写指令之前先看一眼:

| 这个节点在图上 | 它拿到的东西 |
|---|---|
| 没有任何上游(**根节点**) | 流程位置 + 用户的请求 + 你的指令 |
| 有上游 | 流程位置 + **上游步骤的产出** + 你的指令 |
| **开了「读流程记录」** | 流程位置 + **整条流程的记录**(取代上面那一份) + 你的指令 |
| 上游里有分支节点时 | 再加一段「本次执行的前置选择」(开了记录的话它已经在记录里了) |

**指令的键必须叫 `instruction`。** 一个 `prompt` 类的节点没有指令就跑不了(会明确
报错)。这是约定,不是字段 —— 想在界面上改名字的话,改 `label`。

### 「流程位置」是代码给的,别在指令里重复

每一轮的开头都有一段:整条流程有哪几步(**只给名字**,不给各自的指令)、你在哪一格、
你后面还有谁。它不是装饰 —— **跑这一步的是一个独立会话**,看不见别的步骤,不给它看
整条流程的话,第一个节点会收到"用户要一篇综述"+"让我生成计划",然后**把整篇综述写
完**,下游拿到一份成品,没活可干。用户看到的现象就是"第一步把整件事干完了,后面没
传下去"。

**为什么只给名字**:别人的指令对它没用(白烧 token),而且会引诱它越界 —— 看见
"写初稿要写哪几节",它顺手就写了,而我们要的恰恰是它别写。

所以写指令的时候,三件事:

- **别在指令里写"你是第一步"** —— 那一段已经有了,而且它说的是**真的**(从图算出来的);
- **该按住就按住**:「**只**列出要查哪几个方向,正文留到写初稿那一步」。那一段会替你说明
  "后面还有人接着做",但"这一步做到哪儿"只有你能说;
- **末尾写一句「做完的样子」**:做到什么程度算完成、交出什么才算齐。

最后那条不是客套话。**模型靠它判断自己能不能收工** —— 少了它,它容易做一半就停下,
而下游拿到的是个半成品(现象是"这步看着挺像回事,下一步却没法用")。它和「产出变量」
是同一件事的两面:那张表说**交什么**,这一句说**交成什么样才算够**。

> 写在哪都行 —— 指令的末尾,或者「期望产出」那一栏。**两者会拼进同一段提示词**
> (见下面「一个 prompt 节点拿到什么」),模型读到的是一整段,不分会分岔。

**非根节点看不到用户的原话。** 这是刻意的:每一步只拿"它需要的那些上游结果",而不是
整段对话 —— 图越大越省 token,也是这套东西存在的理由之一。代价是**指令必须自足**:

- ✅ `"把上游给出的三篇文献整理成一张对照表,列:问题 / 方法 / 样本量"`
- ❌ `"把上面的结果整理成表格"` —— 这个节点看不到"上面",它只看到上游的产出

上游结果按 `### <上游节点的标题>` 分段拼在你的指令前面。上游有任何一个**没成功**,
这一步就**不会跑**(它在对话里显示成「未运行」),不存在"拿半截结果往下走"。

**例外:被点名的那几步不再整段拼。** 如果指令里已经引用了某一步的产出
(`{{检索.年份}}`、`{{检索.output}}` 这种),那一步的结果就**不会**再自动拼一遍 ——
你点名要了,代码就当你拿到的是想要的那份。这两条是**互斥的两种取法**:点名是"我要
这个",不点名才是"整段都给我"。

不带产出的引用**不算点名**,上游结果照给:`{{某步.params.某参数}}`(要的是配置)、
`{{某步.status}}` / `.error` / `.title`(要的是那一步的元信息)都是。

> 为什么要有这条:两条道都通的话,同一个节点的东西会以**两种形状**在同一段提示词里
> 出现两遍(一遍是干净的值,一遍是原始全文),既白烧 token,又逼着模型去判断"这两份
> 是不是一回事"。

## 运行前先问我:把「跑一步看一眼」收进这一步

上面那套「回头」要用两次:**先拉一个分支节点,再从它拉一根线指回上一步**。为的是同一
件事,但得画两样东西,而且那个分支节点只会问"往哪条路走" —— 说不出"就用这一步自己的
指令"。

对话节点上有个开关「**运行前先问我**」。打开它**不用改图**:跑到这一步会先弹一个框,
四选一。

| 选项 | 输入框 | 选了之后 |
|---|---|---|
| 用这一步的指令 | 有(补充说明) | 照常跑,你补的那句话接在指令后面 |
| 跳过 | 无 | 这一步不跑,直接进下一个节点 |
| 重复上一个任务 | 有(说清哪里不对) | 上一步**连同它的后续**作废重跑,跑完**回到这一步再问一次** |
| 退出流程 | 有(退出后要说的话) | 整张图收场;那段字作为**你的下一条消息**发进对话 |

四条**都不是图上的边** —— 它们是代码给的(见 `@contracts/nodeType` 的 `ASK_CHOICES`)。
所以图上一个环都不用画。少了上游那一步时(根节点),"重复上一个任务"**根本不会出现**。

**「重复上一个任务」里写的那句话,重跑的那一步看得见。** 它作为一条"用户的要求"进流程
记录(和岔路口上你写的那句一样),而被作废重跑的那些节点**从这一轮起按"在环上"对待**
—— 环上的步骤默认读流程记录,于是它睁开眼就能看到"上一版哪里不对"。

> ⚠️ **它绕圈靠的是你每次点一下**,和「回头」同一条道理:结构上停得下来,不是靠
> "最多 N 轮"的计数器兜着。所以也可以一直点"再来一次" —— 那是你的决定。

**关掉那个弹窗不算放弃。** Esc、点外面、或者那个「先放一放」都只是**收起这个框** ——
对话里那张卡还在,点它一样能选。这也是改天回看时唯一说得清"当时选了什么"的地方。

## 关掉应用也没关系

一次运行**跑到哪儿了**,应用替你记着(存在数据根那个库里)。所以卡在一处岔路口上时你
可以随时合上电脑:下次打开,对话里那张卡片还在,**点它就能接着往下跑**。

三条要说清的:

- **只有"正停着等你点"的图能接着跑。** 已经跑完的、你按了停止的,都结束了 —— 那两张
  卡片点了会说一句"这条选择已经不适用了"。那不是错误,是那句话字面的意思。
- **跑到一半的那一步会重跑。** 它当时正在一个独立的会话里干活,而那个会话跟着应用
  一起没了,没有产出留下 —— 所以只能从头再来一遍。**已经跑完的步骤不受影响**,不会
  被重做,也不会被重新判一遍("没走这条路"的那几步同样保持原样)。
- **这个对话换了工作流就不能续了。** 存档里的节点和边是按当时那张图记的,拿它去跑
  另一张图没有意义 —— 那种情况下这张卡片按过期处理,重新发一条消息就是了。

**正在等你拍的岔路口不止一处时,每一张卡片都算数。** 两处岔路口可以同时就绪(它们
互不依赖),于是两条都在等人 —— 你先点哪一条都行。

### 停在等人的时候,你照样可以直接说话

图停在岔路口上等你点的时候,输入框没锁 —— 你把话说出来,**等于放弃这一次、按你说的
重来**。这比"必须先在卡片上点一下"更接近人做事的顺序:你看着那两条路都不太对,想说的
是「算了,换个方向」。

**有节点真在跑的时候不行。** 那时图在干活,半路掐掉一个步骤是「停止」按钮的事,不该由
"我发了条消息"顺手做掉 —— 那种情况下仍然会说一句"这个工作流还在跑"。

> ⚠️ 一个已知的粗糙处:**接着跑**的那一次不会点亮界面上那个"正在运行"的状态(那个状态
> 是跟着你发消息那一下起来的,而续跑时你点的是卡片,没有发消息)。所以那段没有"停止"
> 按钮 —— 但它下次停在岔路口上时,上面那条就说通了:直接说话即可。

## 还能用哪些约定键

除了 `instruction`,还有几个参数**按名字认**:键叫这个,Mcode 就会按这个意思用它。
它们和 `instruction` 一样是**约定而不是字段** —— 界面上想改名字就改 `label`,键不能改。

| 键 | 类型 | 意思 |
|---|---|---|
| `skills` | `ref: "skills"` + `multiple` | 这一步只允许调用这几个技能。留空则由模型自行判断 |
| `mcp` | `ref: "mcp"` + `multiple` | 这一步能用哪几个 **MCP 服务器**。留空 = 全部。**少挂一个就少一整份工具定义进上下文** |
| `plugins` | `ref: "plugins"` + `multiple` | 这一步加载哪几个**插件**(技能 / 命令 / 子 agent 跟着来)。留空 = 所有已启用的 |
| `provider` | `ref: "providers"` | 这一步交给哪家引擎执行(Claude / Codex / …)。留空则与对话保持一致 |
| `context` | `select` + `multiple`,选项取 `library`/`templates` 的分类 | 这一步要读主对话挂载的哪几类**资料** |
| `flowRecord` | `boolean` | 这一步要不要读**整条流程的记录**。缺席 = 按图的结构补默认值(在环上的默认读) |
| `outputContract` | `longtext` | 这一步要交什么的**平实说明**。不强制 |
| `outputVars` | `variables` | 这一步要交出来的东西,**一样一行:名字 + 示例**。会被检查 |
| `returnToChat` | `select`:`none` / `result` / `full` | 这一步跑完之后,有多少东西**并回主对话**(见上面「回到主对话」)。缺席 = `none` |

### 技能 / MCP 服务器 / 插件:同一句话的三个宾语

这三样是**同一条读法**:留空 = 不限制,填了 = 只要这几个。差别只在"限制下去省的是什么":

- **技能**省的是模型的选择面(它少了一个可以调用的东西);
- **MCP 服务器**与**插件**省的是**上下文** —— 一个 MCP 服务器进上下文的不是名字,是它的
  **全套工具定义**(浏览器那一套有二十来个);一个插件带的技能 / 命令 / 子 agent 也各带一段
  说明。而模型每一次调用都要把上下文整段重发一遍,所以"这一步用不到"的东西挂着就是每一轮
  都在花的钱。一个「整理稿子」的步骤挂着浏览器工具,是最典型的那种浪费。

三条规矩:

1. **候选只能往下减。** 这三个参数里只列**这次对话已经能用**的东西(已启用的服务器 / 已授权
   的 / 已启用的插件)。节点关不掉骨干,也打不开用户关掉的东西 —— 那种"选了却不生效"的字段
   比没有更糟。
2. **库里那两个服务器(`mcode-library`、`mcode-workflow`)始终挂着**,不出现在候选里,写也
   写不进去。它们是应用的骨干,不是可选装饰。
3. **插件自带的 MCP 服务器不跟着插件走。** 插件是一整包(技能 + 命令 + 子 agent),但它带的
   服务器在 `mcp` 那张表里**按名字**选(名字是 `<插件>__<服务器>`)—— 所以"只要这个插件的
   技能、不要它那份服务器"是分得开的。

> ⚠️ 收窄是有代价的,而且只在**这一刻**生效:选中的服务器要由 Mcode 显式挂上去。这一步跑起来
> 时用的是"你勾的那几个",不是"设置里开着的那些"。想恢复成"全都给"就把这个参数清空 ——
> 空着走的还是老路(应用读配置、按设置面板的开关挂),行为和从前一字不差。

## 上下文继承:这一步能读哪几类资料

`context` 填的那几类,指的是**主对话已经挂上的**那些附件(输入框里那几行 `@`)。代码把它们
按类目筛一遍交给这一步 —— **不去库里翻,也不生成新清单**:同一批文件、同一份说明,只是
一个子集。所以主对话没挂那一类,这一步就是没有。

给出去的是**清单文件的路径**,不是内容,而且**按"拿来干什么"分成两组**:

```
## 这一步可以读的资料
以下是主对话中挂载的资料。方括号内是它的类别,`@` 之后是它的清单文件路径 —— 用读文件的工具打开,清单中列出具体条目及各自的路径:

**当资料查** —— 读取其内容,事实、方法、数据均在其中:
- 【文献·单篇】@D:/Mcode/library/collections/9f8e7d6c.md

**当格式仿** —— 参照其形式(排版、章节划分、措辞口吻),内容写这一步自己的,不要搬用其中的原话:
- 【Word 模版·类目】@D:/Mcode/templates/.manifests/word.md
```

**两组是两种东西,不是同一个集合的两种颜色。** 文献 / 教材 / 笔记是**拿来查的**(事实、
方法、数据在里面),模版是**拿来仿的**(要的是样子)。平铺成一个列表摆出去,模型多半会把
模版当资料读(于是抄了里面的内容),或者把一篇文献当成格式样板 —— 所以每一组都带一句
"它是拿来干什么的",而不只是给个类目名。

一组里没有东西时那一组整个不出现:只勾了文献的节点不该看见「当格式仿」这几个字。

> 判据是**结构上**现成的:`NodeContextKind` 本来就是 `LibraryKind | TemplateKind` 两个不
> 相交的集合拼出来的,两个库连根目录都不是同一个。

方括号里那两个词(类目 + 它占哪一层:整库 / 分类 / 单篇 / 类目 / 单条)也都是**代码算出来
的** —— 清单的 id 是不透明的(条目的文件名甚至是 sha256),**没有这抬头,模型只能先读一遍
才知道那是一整库还是单独一篇**,而在读之前它会按上下文猜一个。模版那几个抬头**带「模版」
二字**(`【Word 模版·类目】`),免得"Word"被读成那个软件而不是那一类模版 —— 它和你在
`context` 下拉里勾选时看到的词**逐字一致**(见 `contextInherit.ts` 的 `KIND_LABEL`)。

写指令时不用解释这两个词,也不要去猜路径。要它读哪一类,在 `context` 里勾上;要不要读、
读哪一份、怎么用,是模型自己的事。

## 产出变量:这一步交什么,下游取什么

`outputVars` 是一张表,一行两栏。**示例那一栏必须填** —— 它比任何描述都更能说明那一样
东西该长什么样,而且它就是交给模型的样板。

写清单的人看到的是「名字 + 示例」,但在**运行时**底下是一段可以按名字取值的东西:这一步
跑完,代码会去它的产出里把表上那几样找出来,找不到就**这一步失败**(而不是把一段不完整的
东西递给下游,让问题换个地方才炸)。

判定用的是"**能从产出里提出一个对象**",不是"整段必须长这样":模型围着结果说一句话、
或者把它放进 ` ``` ` 围栏里,都算过。**表上没有的名字一律取不到** —— 那张表是一句承诺,
不是"最好有"的清单。多出来的字段要是也能引用,下游的失败就成了随机的(今天跑得通明天跑
不通),而图上没有任何地方看得出为什么。

**填了表,这一步的产出就只有那个对象。** 给模型的措辞是照这个来的:除了它,**别的什么
也不要写**(不要开场白、不要解释、不要总结)—— 这几样要说的内容都写在**值里面**,不在
对象外面再说一遍。所以别把 `outputVars` 当成"挂几个标签",那个值就是**全部内容**;
要长就让它长。

反过来说,**界面不会把那段原文摊给用户看**:卡片是把解出来的变量逐项渲染出来的。所以
这条约束越硬,界面上越干净 —— 两者是一件事的两头。

**最后一步例外:它没有下游,那张表就不发也不查。** 变量表是**给下游取值的**,没人来取
的时候,逼着模型把交付物写成一个对象只有坏处 —— 用户看到的就是一坨 `{"变量名": "…"}`。
所以终末节点该写什么写什么,**按给人看的样子交**。

表上定过的名字,下游**取得到**:

```
把 {{检索.年份}} 填进参考文献
```

`{{...}}` 就是**变量引用**,写在哪都行(通常写在 `instruction` 里)。能写:

| 写法 | 取的是 |
|---|---|
| `{{某步.变量名}}` | 那一步 `outputVars` 里填过的东西 —— **只有填过的才取得出来** |
| `{{某步.output}}` | 那一步的结果文本(整段) |
| `{{某步.status}}` / `.error` | 成功 / 失败 / 跳过,以及失败原因 |
| `{{某步.title}}` | 那一步的标题 |
| `{{某步.params.某参数}}` | 那一步的**配置**(不是结果) |
| `{{user}}` | 用户这次发的请求 |
| `{{trigger.*}}` | **这次是怎么被触发的**(只有触发器起的运行才有,见下) |

### `{{trigger.*}}`

自动化被触发时,这次运行的**起因**也进变量系统。有哪几项**取决于触发方式**:

| 触发方式 | 有哪些 |
|---|---|
| 定时 | `kind`(恒为 `trigger.kind` 那一格,值 `schedule`)、`at`(到点那一刻的毫秒数) |
| 文件变化 | `kind`、`files`(变了的那几个文件的绝对路径) |
| 事件发生时 | `kind`、`event`(钩子事件名)、`toolName` / `subjects`(这个事件有的话);听的是资料库那两个事件时还多 `itemId` / `itemKind` / `itemTitle`,下载完那条多一个 `pdfPath`(库内相对路径) |

「立刻运行一次」跑的是**任何**一种触发器,那时载荷恒是 `manual`,所以 `kind` 一直在。

⚠️ **只有那种触发真的带得出的才写**。一个定时自动化里写 `{{trigger.files}}` 会让那
一步**当场失败**(`载荷里没有它,可用的有:…`)—— 用户盯着按钮的时候失败,还算好的;
配在无人值守的自动化里,是它安静地不跑。设置界面那个「插入变量」菜单按触发器**算**过
一遍,列出来的就是这一种真取得到的 —— 手写的话照上面那张表对。

事件触发那一路的条目事实**可能不止一条**:触发器有合并窗口(默认 2 秒),窗口里连着来的
事件合成一次运行,载荷上会写「一共有 N 条,这次都要办」。那两个单数名字
(`{{trigger.itemId}}` 等)取的是**第一条**,条数看 `{{trigger.itemCount}}`;要办全部就
读载荷里那段话(它一条一行列着),别只照 `{{trigger.itemId}}` 办一条。

某一步可以写 id,也可以写标题(**标题重名时报错,改用 id**)。**只能引用这一步上游的**
节点 —— 图上有、但不是你的上游,一样会报错。

> 设置界面里**不用手写这些花括号**:指令那一栏下面有「插入变量」,上游定过什么就列什么,
> 点一下插到光标处。手写这条路照样通,留给读提示词、从别处拷一份指令过来的人。

变量名不能叫 `output` / `status` / `error` / `title` / `user` —— 那几个是内置的,撞上了那
个变量就永远取不到(内置的先生效)。填表时会被拦下来。**也不要用 `trigger` 当步骤名**
(它是上面那一组的名字空间)。

指令里真要写两个花括号,用 `\{{` 转义。**引用的东西解不出来就让这一步失败**,不会原样
留着 —— 留着的话模型会看见一句带 `{{...}}` 的指令,然后自己编一个值填进去。

## 也可以让 AI 写

对话框里的 AI 手上有一套工具(见 `main/mcp/mcodeServer.ts`),和这里有关的两个是
`node_types_list`(看现在有哪些类型、参数怎么填)和 `node_type_write`(写一份清单进来)。
所以「帮我做一个新节点」这句话是能直接用的。

两条边界:

- **写操作会弹审批**,你点了同意才落盘,落盘位置就是这个目录;
- 它写的也只能是**数据** —— 下面那几样字段。执行方式用的是上面那几种**现成的原语**
  (`prompt` / `conversation` / `branch` / `command` / `code`),不能自己发明,而自带脚本的
  `command` 那种**跑不了**(见「执行方式」)。

另外 `mcode.` 是内置类型的保留前缀,AI 和第三方写的类型都不能用它。

## 改完怎么生效

**不用重启。** 每次打开设置里的工作流页都会重新读这个目录。写坏了也不影响别的:
那个文件会出现在面板的"读不进来"列表里,附上具体错误。

## 分享给别人

把一组节点类型连同脚本装进一个**插件**就能分发:插件根目录放一个 `node-types/`
文件夹(或在 `plugin.json` 里用 `nodeTypes` 指到别处),对方从设置 → 插件里装上即可。
插件里带的东西装完默认是**关**的,开了才生效。
