# hover / 按下 状态体系

> **这个目录是「悬停与按下状态」这一类问题的入口。**
> 代码分散在几十个组件文件里，注释也跟着分散；而**这里**是下一个人要改 hover 时会打开的地方。

## 一、三个角色，各管一段

| 东西 | 是什么 | 定义在哪 |
|---|---|---|
| `--surface-hover` | 悬停填充 | `styles.css` `:root` / `.dark` |
| `--surface-active` | 按下填充（2026-10-24 才拆出来） | 同上 |
| `--selected-bg` / `--selected-content` | 选中行 | 同上 |
| `.cds-hover-ghost` | 把 hover + active 打包成一个类 | `styles.css` 末尾 |
| `.cds-card-interactive` | 悬停抬起 + 阴影，给卡片用 | 同上 |

### 四个状态的取值（T128 定的）

| 状态 | 亮色 | 暗色 | 说明 |
|---|---|---|---|
| 静止 | `--surface` `#fcfcfb` | `#151515` | |
| 悬停 | `--surface-hover` `#f0efec` | `#2c2c2a` | 对静止底 1.120 / 1.305 |
| 按下 | `--surface-active` `#e1e0d9` | `#383835` | 对悬停底 1.151 / 1.190 |
| **选中** | `--selected-bg` `#e7e6e1` + 品牌色文字 + `font-medium` | `#383835` + `#f09978` | **换色系，不是加深** |

**选中不靠更深的灰** —— 上游 `DraggableSessionList.tsx:234` 的四态就是这样：底色只到 10% 中性灰，**区分靠文字变品牌色 + 加粗**。

## 二、`.cds-hover-ghost` 能用在哪儿，不能用在哪儿

**判断标准只有一句：这个元素是不是「用户按下它会期待它凹一下」的控件。**

| ✅ 可以用 | ❌ 不能用 | 为什么 |
|---|---|---|
| 真正 `<button>` 本体 | **整行可点容器**（`ClickableRow`） | 按下时整行缩放 |
| 图标按钮 | **菜单触发器**（`Menu.Trigger` / `ContextMenu.Trigger`） | 同上，且菜单开合有自己的动效 |
| 工具栏按钮 | **拖拽手柄**（`ThreePaneLayout.tsx:98`） | `:active` 在拖动**开始瞬间**触发，干扰手势 |
| 分段控件的**未选中分支** | **选中态分支** | 选中行常驻，不该在按下时缩 |
| | **允许拖选文字的区域** | 拖选时整块轻微缩放，极难在截图里发现 |

**这条类自带 `:active { transform: scale(0.98) }`** —— 那是「按下某个按钮」的手感。**挂错地方不会报错，只会手感怪。**

## 三、为什么还有 29 处没走这个类（27 条裸类 + 2 条有意保留）

**不是欠账，是三个不同理由：**

### 理由一：alpha 变体（27 处）

```bash
grep -rhoE "hover:bg-surface-hover/[0-9]+" apps/desktop/src/renderer --include=*.tsx | sort | uniq -c
#  36 /60   9 /50   6 /70   2 /45   2 /40   ← 五档
```

**换成 `.cds-hover-ghost` 会从「60% alpha」变成「实色」，那是改变画出来的值，不是改写法。**
`/60` 对画布只有 1.071:1，实色是 1.120:1 —— **人眼能看出来**。

**这五档本身也是不一致**（40/45/50/60/70 各写各的），但它们怎么统一是另一个决定，还没做。

### 理由二：同一控件的两个分支分属两套机制（1 处）

`chat/PlanStreamBlock.tsx:111`：
```tsx
hasApproval
  ? "… hover:bg-accent/10"
  : "… hover:bg-surface-hover"
```
迁过去会让**同一个按钮的两个状态用两套 hover 机制**。

### 理由三：拖拽手柄（1 处）

`layout/ThreePaneLayout.tsx:98` —— 见上表。

## 四、判据在哪，各守什么

全部在 `main.ts`，40 条断言，**分八段**：

| 段 | 守什么 | 关键断言 |
|---|---|---|
| [1][2] | 三级阶梯在亮/暗两套里都成立 | `active ≠ hover`、`active 对画布 ≥1.20`、`active 对 hover ≥1.10`、单调 |
| [3] | 两个类真的存在，且 `:active` 与 `:hover` 消费不同 token | `:hover 用 surface-hover` / `:active 用 surface-active` |
| [4] | 示范组件 `button.tsx` 接上了，且不再有裸 hover | `secondary/ghost 用 cds-hover-ghost` |
| [5][6] | tailwind 暴露了 `surface.active`；**裸 hover 总数不回升** | 基线 **29**（含 alpha 变体；纯裸类是 27） |
| [7] | 选中态是换色系 | `selected-bg ≠ hover`、**文字对选中底 ≥4.5:1（AA）**、**文字是彩色不是灰** |
| [8] | **类挂对元素、挂对分支** | `ClickableRow`/`ContextMenu.Trigger` 上没有类；**选中态分支上没有类**；至少有 `<button>` 上有（正控） |

### 第 [8] 段为什么存在

它是**两次真实错误**逼出来的：

1. 把类挂到了 `BrowserToolbar` 的 `ClickableRow` 上，**36 条断言全绿** —— 没有任何一条看「谁承载了这个类」。
2. 把类插进了 `CustomUiToolbar:100` 的**选中态分支**（我的脚本匹配错了分支），**套件也没红**。

**第 2 个是我核对 `git diff` 时自己发现的** —— 这一个动作是套件补不上的。

### ⚠️ 这些判据的边界

- `[8]` 的正则是**匹配元素标签**，抓的是形状不是语义。用别的方式构造的行容器会漏过。
- `[7]` 只验了 `StreamSidebar` 那一处的选中态写法，**别的文件里的选中态没有逐条验**。

**没有假装守住。**

## 五、迁移动过的地方（十三批，310 → 29）

| 批 | 目录 | 形态 |
|---|---|---|
| 1 | `button.tsx` + 四个 layout | 建立示范 |
| 2 | `FileEditor` 等四个高密度 | 原生 `<button>` |
| 3 | `settings/` | **全是 `<Button>` —— 删的是死覆盖** |
| 4 | `library/` | **和 settings 相反：全是原生 `<button>`** |
| 5 | `customUi` / `memory` / `mobile` | 原生 |
| 6 | `browser/` | 原生 |
| 7 | `ide/` | 原生 |
| 8 | `layout/` | 原生，排除拖拽手柄 |
| 9 | `chat/` | 原生，逐个核过不是整块卡片 |
| 10 | `monitoring` / `sidebar` + 补充 | 原生 |

**第 3 和第 4 批形态完全相反** —— 如果按统一规则批量处理，**两个都会做错**：
- `settings/` 上「迁」→ 给 `<Button>` 外面再包一层类，制造新的重复
- `library/` 上「删」→ 真的删掉了唯一的 hover

**`Button` 组件为什么会被重复声明**：`cn()` 是 `twMerge`，它不认识 `.cds-hover-ghost` 这个自定义类，所以两者会同时留在 DOM 上；而两条规则算出的**颜色完全相同**（实测，见下）。于是那段裸类**读起来像在做事，实际什么都没做**。

**`button.tsx` 的文件头现在记了这件事**，防止继续长出来。

## 六、怎么验的（方法，不是结论）

**值不是挑的，是算的。** `--surface-active` 要同时满足「对画布可辨」和「对悬停底区分得开」，和 `--edge` 那次同型。

**「死代码」不是推的，是读的。** 用 `npx tailwindcss` 真实产出一份 CSS，在浏览器里用 CSSOM 读出两条 `:hover` 规则的实际 `background`，确认它们解析到同一个值。

**「判据有效」不是声明，是手工构造一个它没见过的形状。** 放宽判据之后，用第三种背景类（`bg-surface-muted`）再验一遍。

## 七、还没做的

- **27 处 alpha 变体的统一** —— 那是观感决定，要单独评估
- **`scale(0.98)` 的按下手感在真实 Electron 里没人按过** —— 静态截图拍不到动态交互
